# 중앙 회원과 방명록·댓글 작성자 연결 — 실행 계획

상태: Step 1~6 완료, Step 7 미착수. 2026-09-23.
대상: [백로그 1번](backlog.md). 사용자가 Step별로 순차 실행을 요청한다.
저장소: 개인 사이트 `cyworld`, 중앙 인증 `minihompy-central`.

## 범위와 기본 정책

- 중앙 회원으로 로그인한 작성자는 다른 브라우저에서도 같은 회원 소유권을 가진다.
- 글과 댓글은 방문 대상의 개인 Supabase에 저장한다. 중앙에는 콘텐츠나 비밀번호를 저장하지 않는다.
- 비회원 작성은 현재 동작을 유지하는 것을 기본안으로 한다. 기존 익명 글은 자동으로 회원에게 귀속하지 않는다.
- 작성자 식별은 이름이 아니라 검증된 중앙 회원 ID로 한다. 개인 Supabase UUID와 중앙 회원 UUID는 다른 식별자다.
- 중앙 장애나 인증 만료 시 회원 쓰기를 익명 쓰기로 자동 전환하지 않는다.
- 홈 주인은 남의 글을 삭제하거나 방명록을 비공개로 전환할 수 있지만 남의 본문을 수정할 수 없다. 댓글은 부모 글 조회 권한을 따른다.
- 과거 홈 주인이 개인 계정으로 쓴 글은 해당 개인 관리자 인증으로 계속 관리한다. 중앙 회원 ID로의 일괄 이전은 하지 않는다.
- 일촌, 파도타기, 홈 집계는 범위 밖이다. 작성자 이름·회원 구분·검증된 홈페이지 정보를 제공하는 부분까지만 포함한다.

## 구현 방향

브라우저의 방문자 표시 객체를 권한 증거로 사용하지 않는다. 중앙이 발행한 대상 사이트 한정 증명을 개인 Edge Function이 서버에서 확인하고, 해당 사이트의 제한된 회원 세션으로 교환하는 방식을 기본안으로 한다. 개인 서버가 확인한 회원 ID를 내부 DB 작업에 전달한다.

중앙 서명 비밀키를 개인 프로젝트에 배포하지 않는다. 세션 수명·갱신·폐기와 증명의 일회성/재사용 방지 계약은 Step 1에서 확정한다. 현행 60초 방문 티켓과 화면 표시 캐시는 장시간 글쓰기 인증으로 그대로 사용할 수 없다.

회원 작성 행은 기존 익명 작성 경로와 명확히 구분한다. 브라우저가 중앙 회원 ID를 직접 지정하거나 직접 DB 호출로 회원 행의 권한 검사를 우회하지 못하도록 한다. service-role로 기존 RLS를 우회해 접근할 경우에는 회원·부모 글·소유권 검사를 수행하는 제한된 DB 함수 경로를 사용하고 함수 실행 권한도 제한한다. 기존 auth.uid() 기반 트리거·작성 제한도 함께 조정해야 한다.

## Step 1. 권한 계약과 DB 기반

완료: [권한·인증 API 계약 v1](member-writing-contract.md), `202609230001_member_writing_foundation.sql`, [로컬 검증 기록](verification/member-writing-step1/README.md). 운영에는 적용하지 않았다.

개인 저장소 중심. 운영 DB에는 아직 적용하지 않는다.

- 익명 작성자, 중앙 회원 작성자, 홈 주인의 권한표와 서버 API 계약을 확정한다.
- 회원 세션의 발급·만료·갱신·로그아웃 범위, 대상 사이트 바인딩, 증명 재사용 방지 방식을 문서화한다.
- 두 콘텐츠 테이블의 회원 작성자 필드·제약·인덱스와 필요한 내부 세션 저장 구조를 추가하는 마이그레이션을 작성한다.
- 기존 행의 author_id와 내용·비밀글 상태를 보존한다. 기존 직접 쓰기 경로에서 새 회원 필드를 위조할 수 없게 한다.
- 회원 단위 작성 제한, revision 충돌, 요청 재시도 시 중복 방지 계약을 정한다.

완료 기준: 로컬 DB에서 기존 데이터 보존·기존 익명 동작·회원 식별자 직접 주입 거부 검사가 통과하고, 다음 단계에서 사용할 API/권한 계약이 확정된다.

## Step 2. 중앙의 회원 작성 인증 증명

완료: 중앙 저장소의 `202609230002_member_writing.sql`, `identity-api/writing-auth.js`, 서버 로그아웃 연결. [검증 기록](verification/member-writing-step2/README.md). 중앙 전체 12개 테스트 스위트와 브라우저 로그인 회귀 검사 통과. 운영에는 적용하지 않았다.

중앙 저장소 중심. 아직 개인 사이트 쓰기 UI는 변경하지 않는다.

- 로그인한 중앙 세션으로 대상 개인 사이트에 한정된 인증 증명을 발급한다.
- 개인 서버가 증명을 검증/교환할 수 있는 서버 간 경로를 구현한다.
- 회원 ID·표시 이름·등록 홈페이지는 검증된 중앙 데이터에서 반환한다.
- 기존 방문자 인식과 새 작성 인증을 함께 사용할 수 있도록 호환성을 유지한다.

완료 기준: 위조·만료·다른 사이트 대상·비활성 회원·정의된 재사용 위반을 거부하고 기존 로그인 테스트도 통과한다. 중앙의 비밀번호 비보관 원칙을 유지한다.

## Step 3. 개인 서버의 회원 세션과 공통 권한 처리

완료: 개인 `member-writing` Edge Function, service-role 전용 세션 RPC, 공통 클라이언트. [검증 기록](verification/member-writing-step3/README.md). 중앙/개인 실제 SQL 연계 10개 그룹·클라이언트·Pages artifact 검사 통과. 운영에는 적용하지 않았다.

개인 저장소 중심. 방명록/댓글 공통 기반을 먼저 구현한다.

- 개인 Edge Function이 중앙 증명을 확인하고 사이트 한정 회원 세션을 발급한다.
- 세션 확인·갱신·폐기와 프런트엔드 공통 클라이언트를 구현한다.
- 요청의 회원 ID를 신뢰하지 않고 서버가 확인한 주체로만 내부 DB 작업을 수행한다.
- 관리자 권한은 별도 개인 인증으로 확인하며 방문 회원에게 관리자 권한을 부여하지 않는다.
- 회원·익명·관리자 모드를 명시적으로 선택하고 인증 실패 시 자동 익명 전환을 막는다.

완료 기준: 세션 변조/만료/폐기, 타 사이트 세션, 회원 ID 바꿔치기를 거부한다. 새 인증이 기존 관리자 및 익명 세션을 덮어쓰지 않는다.

## Step 4. 방명록 연결

완료: 회원 방명록 RPC/API·화면과 중앙 증명 왕복 연결. [검증 기록](verification/member-writing-step4/README.md). 회원 통합 8개 그룹·새 브라우저 회원 소유권·기존 익명 데스크톱/모바일 회귀·중앙 12개 스위트 통과. 기능은 기본 비활성 상태이며 운영에는 적용하지 않았다.

- 방명록 조회·등록·수정·삭제·비공개 전환을 새 회원 경로에 연결한다.
- 회원 작성 시 검증된 이름을 표시하고 이름을 자유 입력하는 익명 모드와 구분한다.
- 작성자 홈페이지 정보를 제공하고 검증된 주소만 사용한다.
- 비밀글 본문과 건수/페이지 결과를 주인·작성자에게만 허용한다.
- 회원 기준 작성 제한과 충돌·응답 유실 시 중복 방지를 유지한다.

완료 기준: 로컬 통합 환경에서 A가 B에 쓴 글을 새 브라우저의 A가 관리할 수 있고, 다른 회원/비회원은 소유권을 얻지 못한다. B 주인의 삭제·비공개 전환과 본문 수정 금지도 확인한다. 기존 익명 글도 회귀 검사한다.

## Step 5. 공통 댓글 연결

완료: 네 부모의 회원 댓글 RPC/API·공통 화면 연결. [검증 기록](verification/member-writing-step5/README.md). 회원 통합 9개 그룹·Chromium 새 브라우저 소유권·최신 DB의 익명/관리자 권한·기존 댓글 데스크톱/모바일 회귀 통과. 운영에는 적용하지 않았다.

- 게시판·사진첩·다이어리·방명록 댓글에 같은 회원 작성자 모델을 적용한다.
- 작성자 수정·삭제와 홈 주인의 삭제 권한을 유지한다.
- 비공개 방명록 댓글은 목록·작성·수정·삭제 모두 부모 글 접근 권한을 확인한다.
- 댓글의 회원 기준 작성 제한·재시도·revision 충돌 처리를 연결한다.

완료 기준: 네 종류 부모에 대해 회원/익명/관리자 권한 검사가 통과한다. 부모가 비공개로 바뀌거나 삭제된 후 댓글 직접 접근도 제한된다.

## Step 6. 계정 전환·로그아웃·장애 통합 검증

완료: 개인 세션 서버 폐기와 탭 간 변경 통지, 요청/초안의 주체 검사, 비밀 DOM 정리, 만료·장애 재확인 연결. [검증 기록](verification/member-writing-step6/README.md). 실제 SQL/API 연계 Chromium 수명주기 검사와 기존 방명록·댓글·관리자 회귀 통과. 운영에는 적용하지 않았다.

Step 3의 기본 세션 처리를 실제 화면과 두 작성 기능 전체에서 검증·보완한다.

- A→로그아웃→B 전환 시 입력 폼, 목록, 비밀글 캐시 및 진행 중 요청을 정리한다.
- 오래된 응답이 새 계정 화면을 덮어쓰지 못하도록 한다.
- 로그아웃 시 개인 작성 세션도 서버에서 폐기하고 이전 세션 재사용 거부를 검사한다.
- 새 브라우저 로그인, 다중 탭, 인증 만료·갱신 실패, 중앙/개인 서버 장애를 검증한다.
- 인증이 바뀐 작성 중 내용은 다른 회원으로 자동 제출하지 않으며 복구/재확인 방식을 제공한다.

완료 기준: 계정 간 소유권과 비밀글이 섞이지 않고, 회원 인증 오류 시 익명 글이 생기지 않는다. 방명록·댓글의 전체 로컬 통합 검사가 통과한다.

## Step 7. 설치·업그레이드 지원과 실제 배포 검증

- 신규 설치와 기존 사이트 업그레이드에 DB/함수/비밀 설정을 반영한다. 중앙 서명키는 배포하지 않는다.
- 기존 데이터 보존과 버전 호환성을 확인하고 마이그레이션 적용 순서·복구 절차를 문서화한다.
- 중앙 → 개인 DB/함수 → A/B 화면 순으로 호환되는 버전을 배포하고 기능을 활성화한다.
- 실제 A가 B에 남기는 공개/비밀 방명록 및 댓글, 새 브라우저 소유권 복원, 관리자 관리, 로그아웃/계정 전환을 검증한다.
- 운영 검증은 전용 테스트 글과 댓글을 사용하고 생성한 항목만 정리한다. 기존 사용자 콘텐츠는 변경하지 않는다.
- 결과를 기록하고 백로그 완료 조건을 갱신한다.

완료 기준: 실제 A/B 배포에서 쓰기·권한·비밀글·기존 익명 글 호환 검증을 통과하고 테스트 데이터 정리가 끝난다. 이 단계까지 완료해야 기능 전체 완료로 표시한다.

## 실행 방식

각 Step 요청 시 해당 범위의 코드·문서·검사를 완료하고 다음 단계로 넘긴다. Step 1~6은 로컬 구현과 검증이며 운영 배포는 Step 7에 모은다. 앞 단계의 계약을 변경해야 하면 후속 단계에서 변경 이유와 호환 영향을 함께 기록한다.
