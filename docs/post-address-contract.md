# 최소 글 주소 계약 — 홈 데이터 Step 2

2026-09-23. 로컬 구현. 운영 적용은 홈 데이터 Step 7이다.

## 주소와 화면

`#/board?post=<UUID>`, `#/photos?post=<UUID>`, `#/diary?post=<UUID>`, `#/guestbook?post=<UUID>`를 사용한다. 기존 `#/home`, `#/board`, `#/settings` 등 메뉴 주소를 유지한다. 공통 `MinihompyPostRoutes.href(kind,id)`와 `parse(hash)`를 사용하며 중복 post·알 수 없는 query·잘못된 UUID·지원하지 않는 메뉴의 post는 오류 안내로 처리한다. UUID 대문자는 소문자로 정규화한다. 주소에는 인증 토큰·본문·작성자 정보를 넣지 않는다.

- 게시판: 실제 폴더/페이지를 정하고 해당 글 상세를 연다. 목록 복귀 시 대상 주소를 해제하고 해당 페이지/글로 돌아간다.
- 사진첩: 실제 폴더의 페이지를 열어 글에 포커스/스크롤을 맞춘다.
- 다이어리: 글에 저장된 폴더·날짜·그 날짜 안의 페이지를 선택하고 해당 글에 포커스/스크롤을 맞춘다.
- 방명록: 현재 독자가 볼 수 있는 목록을 기준으로 페이지를 계산하고 해당 항목으로 이동한다. 비공개 글이라도 기존 정책상 소유자/작성자가 조회 가능한 경우는 열 수 있으며, 조회 권한이 없는 독자에게는 존재 여부/내용을 주지 않는다.

초기 설정 로드 중에도 대상 hash를 보존한다. 중앙 방문 티켓 처리 중에는 라우터가 hash를 덮지 않고, 기존 방문자 모듈이 복구한 경로로 진입한다. 제목/본문은 기존 뷰의 텍스트 출력 규칙을 유지한다. 삭제·조회 불가·숨김 메뉴·잘못된 주소는 이전 글 제목을 남기지 않고 오류를 표시한다. 폴더/날짜/페이지를 직접 선택하거나 목록으로 돌아가면 글 주소를 해제해 새 화면과 주소가 충돌하지 않게 한다.

이번 변경은 홈에서 쓸 최소 진입 계약이다. 모든 내부 목록 클릭을 글 permalink로 바꾸거나 작성 후 복귀/임시저장 체계를 전체 개편하지 않는다. 홈의 최근게시물 링크 연결은 Step 3이다.

## 위치 조회와 권한

`public.post_location(p_kind text,p_id uuid,p_size integer)`는 SECURITY INVOKER, 빈 search_path, 정적 스키마 참조로 구현한다. kind는 네 종류, size는 1~20만 허용하고 ID는 uuid 타입으로 제한한다. anon/authenticated만 실행 권한을 받는다. 원본 테이블 RLS가 대상 조회와 페이지 계산 양쪽에 적용된다.

반환: `{id,folder_id,entry_date,page}` 또는 대상 조회 불가 시 null. 글 제목/본문/작성자나 별도 전체 건수는 반환하지 않는다. board/photos는 같은 폴더의 `(created_at DESC,id DESC)`, diary는 같은 폴더·날짜의 `(entry_time ASC,id ASC)`, guestbook은 독자에게 보이는 `(created_at DESC,id DESC)` 순서를 사용한다. 네 종류의 실제 목록과 같은 정렬이다. 위치 계산은 서버 COUNT이며 목록 페이지를 하나씩 반복해서 가져오지 않는다.

RPC 후 실제 내용은 기존 repository를 통해 다시 읽는다. 그 사이 삭제/공개범위가 바뀌어 대상을 찾지 못하면 오류로 처리한다. 바뀐 위치로 계속 반복 탐색하지 않는다. 재시도하면 위치와 권한을 다시 확인한다.

중앙 회원 방명록은 개인 Auth RLS만으로 권한을 표현할 수 없으므로 기존 member-writing 서버 경로를 사용한다. `GET /guestbook?page=1&size=5&post=<UUID>`로 요청하면 기존 `public/member/owner` 검증 후 `member_guestbook('list',...)` 안에서 같은 권한 조건으로 대상 페이지를 계산하고 그 페이지 목록을 반환한다. 대상 불가 404, 잘못된/중복 post 400, 만료/폐기 세션은 기존 오류다. `post` 없는 기존 호출의 응답과 동작은 유지한다. 브라우저는 계산된 `page`를 사용한다.

추가 마이그레이션:

1. `202609230006_post_location.sql`: 위치 조회 RPC.
2. `202609230007_guestbook_post_location.sql`: 기존 member_guestbook 함수를 같은 권한/쓰기 정책을 유지하며 교체하고 list의 선택적 post 처리만 추가한다.

이전 마이그레이션 파일은 수정하지 않는다. 기존 행/폴더/설정에 DML을 실행하지 않으며 재적용을 검사한다. `member-writing/handler.js`와 개인 Pages의 호환 배포/설치 연결은 Step 5/7에서 수행한다.

## 이동과 초안

라우터는 같은 문서의 일반 링크·메뉴 이동·hash 변경·뒤로/앞으로에서 하나의 `minihompy:before-navigate` 검사를 수행한다. 쓰기 중인 상태는 이동을 막고, 변경된 초안이 있으면 확인한다. 취소하면 현재 URL·화면·입력을 유지하며, 관리하는 history 항목의 뒤로가기 취소는 원래 항목으로 돌아가 앞으로가기 기록을 보존한다. 일반 링크의 새 탭·수정키·외부 이동은 브라우저 기본 동작을 유지한다.

기존 동작에 맞춰 일반 메뉴 이동을 승인해도 각 뷰의 메모리 초안은 유지한다. 특정 글 주소를 승인하면 목적지 화면의 충돌하는 글 편집 초안만 초기화한다. 여러 편집기가 있어도 확인/진행 가능 여부를 먼저 수집하고 모두 통과한 뒤 초기화한다. 댓글 초안의 기존 보존 정책은 유지한다. 새 임시저장 저장소를 도입하지 않는다.

늦은 비동기 위치/본문 응답은 기존 뷰 request generation 검사로 배제한다. 다른 메뉴로 이동한 뒤 분리된 DOM을 갱신해도 새 화면에 삽입하지 않는다. 동일 메뉴에서 다른 글로 재진입하면 새 요청 세대가 이전 응답을 무시한다.
