# 사진첩 작성과 이미지

## 현재 동작

- 사진첩은 `photo_folders`, `photo_posts`를 조회한다. 과거 `photos-data.js` 샘플은 실행되지 않는다.
- 폴더는 기존처럼 1단계와 구분선만 허용한다. 초기 실제 폴더는 `일상` 하나다. 관리자는 폴더 생성·정렬·이름 변경·이동 후 삭제를 할 수 있다.
- 관리자만 사진 올리기/수정/삭제를 볼 수 있다. 수정은 해당 관리자 본인 글만 가능하다.
- 본문은 Quill 2.0.3으로 편집한다. 사진 파일 선택 직후 커서 위치에 로컬 Blob 미리보기를 넣는다. 사진 사이에 글을 입력할 수 있다.
- 파일 선택, 이미지 붙여넣기, 파일 드롭을 지원한다. 외부 HTML의 이미지는 붙여넣지 않는다. 이번 단계의 서식은 일반 텍스트와 사진뿐이다.
- 저장을 누르면 사용 중인 새 사진부터 업로드하고, 순서 있는 텍스트/이미지 블록을 JSONB에 기록한다. HTML은 저장하거나 실행하지 않는다.
- JPG/PNG/WEBP/GIF, 장당 최대 6MB, 글당 사진 1~20장, 제목 120자, 본문 50,000자/100블록 이내. 원본을 업로드하며 리사이즈하거나 EXIF를 제거하지 않는다.
- 읽기 화면은 2개 글씩 펼쳐보기와 페이지 이동을 유지한다. [공통 댓글](comments.md)의 작성·본인 수정·삭제를 지원한다.

## 저장과 실패

- 다른 메뉴 이동·문서 이탈 시 초안과 첨부 선택을 확인창 없이 폐기하고 미리보기 URL을 해제한다. 같은 화면의 인증 갱신·일시 오류에서는 유지하며 영구 임시 저장은 하지 않는다. 저장 요청 전 업로드 파일만 미사용으로 정리하며, 이미 저장을 요청한 첨부는 응답이 불확실해도 삭제하지 않는다. 로그아웃하면 초안을 지운다.
- 업로드/DB 저장 실패 시 초안을 유지한다. 업로드 완료 파일은 재시도 시 재사용한다.
- 업로드 응답 유실 후 같은 경로가 이미 있으면 서버 registry의 크기·MIME·SHA-256 receipt를 비교한다. 일치할 때만 재사용하며 덮어쓰지는 않는다.
- 글 UUID는 작성 시작 때 생성한다. 새 글 저장 응답이 유실되어 재시도해도 동일 ID와 내용이 확인되면 저장된 글을 반환한다.
- 수정/삭제는 revision 비교로 동시 변경 충돌을 막는다.
- 수정으로 빠진 사진과 삭제한 글의 사진은 글 저장/삭제가 성공한 뒤 photo-media cleanup으로 정리한다. 서버는 글에 연결된 파일의 정리를 거절한다.
- 저장 시도 전 취소는 서버 파일을 만들지 않는다. 부분 업로드 후 취소는 시도한 경로를 서버에 정리 요청한다. 통신 단절, 브라우저 종료, 로그아웃, 응답 유실은 미사용 파일을 남길 수 있다. 자동 배치 정리는 아직 없으며 서버 registry·본문 참조·진행 중 작업을 확인하고 보호된 cleanup 절차로 복구해야 한다. DB 행을 직접 지워 Storage 파일을 삭제하지 않는다.

## 공개 범위와 권한

현재 로컬 구현은 글별 공개/나만보기를 지원한다. 개인 Supabase에서 검증된 관리자만 비공개 글과 사진을 읽는다. 중앙 방문자 표시는 관리자 권한을 대신하지 않는다. 공개범위 변경은 기존 작성자의 글에도 가능하며 본문 수정 권한은 확대하지 않는다.

사진은 private 버킷 `minihompy-photos-private`에 보관하고 photo-media 서버가 첨부 관계와 현재 권한을 확인한 바이트만 반환한다. 브라우저는 공개/서명 URL을 생성하지 않는다. 보호된 조회는 최대 4개 동시 요청, 표시 범위 내 캐시를 사용한다. 로그아웃·계정 변경·메뉴 이탈·문서 이탈 시 조회를 취소하고 Blob URL을 해제한다. 편집 미리보기도 같은 읽기 경로를 사용한다.

**A/B 운영 전환을 완료했다.** 기존 공개 원본 폐쇄·실제 Storage/Edge 확인·media-ready 활성화와 파일 보존 결과는 [Step 10 기록](verification/folder-visibility-step10/README.md)에 있다. 새 사이트 전환은 [전환 절차](photo-media-migration.md)를 따른다. 이미 내려받은 사본은 회수할 수 없다.

## 검증

- `scripts/verify-photo-visibility-ui.mjs`: 실제 화면·SQL·photo-media handler, 로컬 Auth/Storage 대역으로 권한·Blob 수명·경합 30개 그룹. [Step 8 기록](verification/folder-visibility-step8/README.md).

- `scripts/verify-photos-writing.mjs`: 실제 SDK/Quill + 모의 API, 데스크톱/모바일. 인라인 미리보기, 글/사진 순서, 조기 업로드 방지, 초안 유지, 저장/수정/삭제, 실패/재시도/충돌/로그아웃, 이미지 크기 검사.
- `scripts/verify-photos-db.mjs`: 로컬 PGlite와 최소 Storage 스키마로 마이그레이션, 관리자 권한, 블록 제약, revision, 게시 중 파일 삭제 보호를 검증한다. 실제 Storage 서버의 MIME/파일 크기 제한은 대체하지 않는다.
- 스크린샷: `docs/verification/photos-writing/`.
