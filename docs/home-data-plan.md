## 계획 수립 당시 구현과 부족한 부분

- `views/home.js`는 최근게시물 없음 문구와 메뉴 건수 `0/0`, `0/1`을 고정 출력한다. 데이터 조회나 오류/로딩 상태가 없다.
- `index.html`의 TODAY/TOTAL은 `home.today`, `home.total` 설정에 연결되어 있다. `config.js`도 이 값을 수동 설정 숫자로 검증한다. 실제 방문 집계는 없다.
- 게시판·사진첩·다이어리·방명록과 댓글은 개인 DB에 존재한다. 일반 게시물의 공개범위 관리 UI는 백로그 4번이며, 현재 게시판·사진첩·다이어리는 공개 읽기 정책이다. 방명록 비밀글과 그 댓글은 기존 회원 작성 권한 정책을 따른다.
- `app.js`는 `#/board` 같은 메뉴 주소만 해석한다. 각 뷰의 선택 글·폴더·페이지는 내부 상태라 최근 글을 직접 여는 공통 계약이 없다.
- 로그인 복귀, 메뉴 설정, 미저장 입력 확인, 회원 작성·이동의 계정 전환 처리에 영향을 줄 수 있어 관련 회귀 검증이 필요하다.

## 범위와 기본 정책

아래는 이번 계획의 실행 기본값이다. 사용자가 수정하면 후속 Step에 반영한다. 구현 중 보안·호환성 때문에 변경해야 하면 근거와 영향을 문서에 남긴다.

### 공개 홈 데이터

- 로그인 여부나 관리자 권한과 관계없이 **동일한 공개 집계**를 사용한다. 관리자용 비공개 건수·제목은 홈에 섞지 않는다. 브라우저에서 받은 전체 목록을 나중에 숨기는 방식으로 처리하지 않는다.
- 최근게시물은 게시판·사진첩·다이어리·공개 방명록을 합쳐 최신 5개를 표시한다. 생성 시각 내림차순에 종류·ID를 보조 정렬키로 써서 결과를 안정화한다. 수정만으로 새 글이 되지는 않는다.
- 제목 있는 글은 제목, 제목 없는 다이어리/방명록은 공개 본문을 태그·서식 없이 제한된 길이로 요약한다. 본문 전체나 비공개 원문을 요약 API에 실어 보내지 않는다. 종류·작성 시각·글 ID 등 화면에 필요한 필드만 반환한다.
- 메뉴 건수는 `오늘 / 전체` 공개 글 수로 정의하고 의미를 화면에 표시한다. 지원 대상은 위 네 메뉴이며, 미구현 갤러리·동영상에 임의의 숫자를 표시하지 않는다.
- ‘새 댓글’은 **오늘 작성된 공개 글의 댓글 건수**가 아니라 **공개 부모 글에 오늘 작성된 댓글 건수**다. 읽음/미읽음 또는 개인 알림을 뜻하지 않는다. 오늘의 전체 댓글 수와 최근게시물별 오늘 댓글 수를 제공한다. 삭제된 댓글, 비밀 부모의 댓글은 제외한다.
- 숨김 메뉴는 공개범위가 아니다. 숨김 메뉴의 항목은 홈에서도 노출·이동 대상에서 제외하되, 보안은 DB 공개 조건으로 보장한다. 미래 백로그 4번의 공개범위 구현은 같은 집계 계약과 검사를 확장해야 한다.
- 정상 조회 결과 0건일 때만 빈 상태를 표시한다. 조회 실패·조회 중은 별도 안내와 재시도를 제공한다. 본문을 HTML로 삽입하지 않는다.

### 최소 글 주소

- `#/board?post=<UUID>`, `#/photos?post=<UUID>`, `#/diary?post=<UUID>`, `#/guestbook?post=<UUID>`를 기본 주소안으로 한다. 기존 메뉴 주소와 설정 화면은 호환한다.
- ID로 대상 글을 조회해 실제 폴더/페이지/날짜에 맞는 화면을 열고 해당 글로 스크롤·포커스를 이동한다. 첫 페이지에 없는 글도 찾는다. 임의의 상한까지 목록을 반복 조회하여 찾지 않는다.
- 최초 직접 진입·새로고침·뒤로/앞으로·중앙 로그인 복귀에서 대상을 유지한다. 삭제·비공개·잘못된 ID·숨김 메뉴는 원래 제목을 남기지 않는 안전한 안내를 제공한다.
- 기존 미저장 내용 확인을 통과해야 이동하며 취소하면 URL·화면·초안이 일치하게 유지한다. 전체 작성 흐름/임시저장/주소 체계 개선은 백로그 6번에 남긴다.

### 방문 집계

- 날짜는 서버 시각의 **Asia/Seoul 자정 기준**이다. 오늘 글·댓글 집계도 같은 기준을 사용한다.
- 사이트별 브라우저 임의 식별자를 사용하여 **같은 브라우저가 같은 사이트를 방문하면 하루 1회** 집계한다. 로그인/로그아웃/계정 전환, 탭·새로고침·메뉴 이동·중앙 인증 왕복은 당일 추가 집계하지 않는다. A/B 사이트는 따로 센다.
- 소유자 방문도 포함한다. 기기·브라우저가 다르거나 저장소를 초기화하면 별도 방문으로 셀 수 있으므로 ‘정확한 사람 수’로 설명하지 않는다. 중앙 회원 ID나 로그인 여부를 집계 키로 사용하지 않는다.
- 실제 개인 페이지가 표시 가능한 상태에서 방문을 기록한다. 중앙/개인 로그인 페이지와 비활성 탭의 자동 로드만으로는 기록하지 않는다. 날짜를 넘겨 다시 표시된 페이지의 집계 처리도 검증한다.
- 저장소 사용이 불가능하면 매 요청 새 ID를 만들어 늘리지 않고 기록을 건너뛰며 기존 통계 조회는 유지한다.
- TOTAL은 기능 활성화 이후 서버가 기록한 누적 방문이다. 기존 수동 `home.today/total`은 합산하지 않는다. 과거 설정값 자체는 보존하지만 화면과 설정 UI에서는 실측 통계를 덮어쓸 수 없게 한다.
- 서버는 날짜·증가량을 결정하고 중복 키/트랜잭션으로 동시 요청·재시도를 안전하게 처리한다. 클라이언트의 숫자·날짜를 신뢰하거나 공개 테이블 직접 갱신을 허용하지 않는다.
- 일별 집계와 중복 방지에 필요한 최소 데이터만 보관한다. 원본 브라우저 식별자·IP·회원별 이동 이력을 공개하거나 장기 방문 기록으로 저장하지 않는다. 서버의 일별 해시 키, 보존/정리 기간, 입력 제한·요청 제한을 Step 4에서 구체화한다. 식별자를 바꾼 의도적 부풀리기를 완전히 방지하는 분석 서비스는 범위 밖이며 실제 방어 범위를 기록한다.

## Step 1. 공개 홈 요약 조회 기반

완료: 공개 요약 RPC·읽기 인덱스·조회 repository와 [계약 v1](home-data-contract.md). 실제 SQL 8개 그룹, repository 경계, 기존 회원 방명록·댓글 권한 회귀 및 Pages 검증 통과. [검증 기록](verification/home-data-step1/README.md). 운영에는 적용하지 않았다.

개인 DB와 조회 계층 중심. 이후 화면에서 쓸 계약을 실제 데이터와 함께 완성한다.

- 반환 필드, 최신 5개 정렬, 오늘/전체 건수, 오늘 댓글 수, 메뉴 필터와 날짜 경계를 문서화한다.
- 기존 RLS·회원 작성 함수와 방명록/댓글의 공개 읽기 경로를 점검한다. 관리자 또는 회원 세션으로 호출해도 공개 데이터만 반환하는 제한된 집계 RPC/API를 구현한다.
- 필요한 SQL·인덱스와 홈 조회 repository를 추가한다. 읽기 결과를 bounded size로 제한하고 글별 반복 요청을 피한다. RPC 실행 권한·검색 경로·공개 부모 조건을 검증한다.
- 정상 0건, 비공개만 존재, 섞인 글/댓글, 삭제, 동일 시각, 한국 날짜 경계, 임의 ID·입력, 익명/회원/관리자 호출을 실제 SQL 기반으로 검사한다.

완료 기준: 공개 글·댓글만 동일한 정책으로 집계되고 비공개 제목/요약/건수/식별자가 새지 않는다. 기존 개인 콘텐츠와 작성 권한을 보존한다. 계약과 검증 기록을 남긴다. 운영에는 적용하지 않는다.

## Step 2. 최근 글을 여는 최소 주소 연결

완료: 네 종류 글 주소·권한별 위치 조회·실제 뷰 연결, history/로그인 복귀와 초안 확인·취소 보존. 실제 SQL, 데스크톱/모바일 UI, 중앙 인증 복귀·기존 작성/설정 회귀와 Pages 검사 통과. [주소 계약](post-address-contract.md) · [검증 기록](verification/home-data-step2/README.md). 운영에는 적용하지 않았다.

라우터와 네 종류 글 화면 중심. 홈 UI를 바꾸기 전에 실제 글로 이동할 기반을 완성한다.

- 메뉴/글 ID를 분리하는 공통 주소 파서와 링크 생성기를 추가한다. 기존 메뉴 링크와 외부 중앙 인증 복귀 경로를 유지한다.
- 게시판 상세, 사진첩 해당 글, 다이어리 해당 날짜·글, 방명록 해당 항목을 ID로 연다. 필요한 단건 조회/위치 조회도 이 단계에서 구현한다.
- 대상 폴더·페이지를 결정할 때 목적지의 기존 읽기 권한을 다시 검사한다. 공개 홈에 존재했던 글이 이후 삭제·비공개 처리되어도 내용이 남지 않게 한다.
- 미저장 입력 취소, 초기 설정 로드 중 직접 진입, 새로고침·뒤로/앞으로, 인증 복귀, 존재하지 않는 글을 검사한다.

완료 기준: 네 종류의 첫 페이지 밖 대상까지 실제 열리고, 취소/권한 실패 시 URL·화면이 불일치하지 않는다. 기존 메뉴 이동·초안 보호와 인증 복귀 검사가 통과한다. 운영에는 적용하지 않는다.

## Step 3. 홈의 최근게시물·건수·댓글 표시

완료: 공개 최근 글·실제 건수·오늘 댓글과 글 주소 연결, 로딩/빈 상태/오류/재시도, 재진입·설정·계정 변경과 표시 수명 처리. 데스크톱/모바일 UI·SQL·repository·기존 글 주소/회원 이동/게시판/설정 및 Pages 검사 통과. [검증 기록](verification/home-data-step3/README.md). 운영에는 적용하지 않았다.

개인 화면 중심. Step 1 조회와 Step 2 주소를 연결한다.

- 고정 빈 문구·건수를 실제 목록과 `오늘 / 전체` 숫자로 교체한다. 오늘 댓글의 의미를 명시하고 실제 값에 연결한다.
- 정상 빈 상태·로딩·오류·재시도를 구분한다. 미구현 메뉴의 고정 숫자를 제거하고 숨김 메뉴 변경을 반영한다.
- 홈 재진입, 글/댓글 저장·삭제 후 복귀, 설정 변경 시 갱신한다. 오래된 비동기 응답이 다른 뷰나 이전 상태를 덮지 않게 한다.
- 공개 데이터라도 오래된 캐시가 삭제/비공개 전환 후 계속 보이지 않도록 수명과 무효화 정책을 정한다. 계정 전환으로 관리자 데이터가 섞이지 않게 한다.
- 데스크톱/모바일, 긴 제목·특수문자, 키보드·포커스, 네 종류 이동, 정상 0건과 오류를 검사한다. 화면 확대 설정은 변경하지 않는다.

완료 기준: 실제 글이 있으면 최근 목록과 정확한 건수가 보이고, 클릭하면 해당 글이 열린다. 실패를 0건으로 표시하지 않으며 기존 홈 레이아웃·프로필·미니룸·회원 이동을 유지한다. 운영에는 적용하지 않는다.

## Step 4. 서버 방문 집계와 중복 방지

완료: 개인 방문 기록/조회 API·일별/누적 통계·HMAC 중복 방지·원자적 증가·접근/요청 제한과 만료 키 정리. 실제 SQL/Edge 10개 그룹과 홈 요약·회원 방명록/댓글 회귀 및 Pages 검사 통과. [방문 계약](visit-counts-contract.md) · [검증 기록](verification/home-data-step4/README.md). 다중 연결 부하 검증과 운영 배포는 수행하지 않았다.

개인 Supabase 중심. 화면과 독립적으로 정확한 증가 규칙을 구현한다.

- 기록/조회 API, 일별 집계·누적 집계·중복 방지 저장 구조를 추가한다. 단순 조회는 방문 수를 증가시키지 않는다.
- 임의 브라우저 키를 서버에서 일별 중복 키로 처리하고 원본 키를 보관하지 않는다. HMAC 등 서버 비밀값이 필요하면 초기 생성·교체 시 중복 영향·설치 절차를 명시한다.
- 동일 키 동시 호출·성공 응답 유실 후 재시도에도 한 번만 증가하도록 DB 트랜잭션/유일성을 보장한다. 한국 자정·날짜별 중복, 미래 날짜 입력, 정리 후 TOTAL 유지, 숫자 범위를 검사한다.
- 직접 쓰기 권한을 차단하고 입력 크기·요청 제한을 적용한다. Origin 검사만을 인증 또는 부풀리기 방지라고 간주하지 않는다. 외부 요청·키 회전에 대한 한계를 문서화한다.
- 집계 전용 데이터를 정리하는 정책은 기존 콘텐츠/회원 데이터에 영향을 주지 않게 구현한다.

완료 기준: 실제 SQL/API 검사에서 하루 1회 규칙·원자성·서버 날짜·조회와 기록 분리·접근 제한이 검증된다. 방문 실패가 콘텐츠 표시나 인증을 막지 않는다. 운영에는 적용하지 않는다.

## Step 5. TODAY/TOTAL과 설치·설정 연결

완료: 공통 방문 통계·탭/저장소/날짜/재시도 처리, 수동 숫자 편집 제거와 구버전 저장 호환, 준비 완료 후 활성화되는 신규/기존 설치 명령. 방문 UI·실제 SQL/설치·기존 설정·홈 화면·Pages 검사 통과. [검증 기록](verification/home-data-step5/README.md) · [설치 안내](../setup/README.md#홈-데이터와-방문-통계-설치업그레이드). 운영에는 적용하지 않았다.

개인 화면·설정·설치 도구 중심. Step 4 집계를 실제 방문 흐름에 연결한다.

- 공통 화면의 TODAY/TOTAL을 서버 조회로 교체하고 고정 초기 숫자를 제거한다. 홈 이외의 메뉴에서 직접 진입해도 같은 사이트 통계를 표시한다.
- 식별자 저장 범위를 사이트별로 분리하고 인증 복귀·탭·새로고침·계정 전환에서 중복 키를 유지한다. 보이지 않는 문서/로그인 화면에서 기록하지 않는다.
- 집계 중·실패·재시도를 표시하되 글 읽기·쓰기·로그인을 방해하지 않는다. 저장소 차단, 날짜 변경과 다시 표시된 탭을 처리한다.
- 설정 화면의 수동 방문 수 편집을 제거하거나 읽기 전용으로 바꾸고, 기존 설정 JSON·저장 검증·초기 설치와의 호환성을 유지한다. 옛 숫자를 실측값으로 우회 표시하지 않는다.
- 신규 설치 및 기존 사이트 업그레이드에 요약/방문 SQL·필요 함수/Secrets·런타임을 포함하고, dry run·사전 점검·재실행을 지원한다. 단순 Pages 배포만으로 준비되지 않은 DB를 사용하지 않게 한다.

완료 기준: 탭·재로드·메뉴·로그인 왕복은 한 번, 별도 사이트/브라우저/날짜는 정책대로 집계된다. 수동 설정이 실측 통계를 덮지 않고 구버전 설정도 읽힌다. 설치/업그레이드 검사가 통과한다. 운영에는 적용하지 않는다.

## Step 6. 실제 데이터·권한·이동 통합 검증

완료: 실제 개인 SQL/Edge와 브라우저의 네 종류 글·댓글 생성/홈/이동/삭제, 공개 필터·역할 전환·방문 중복/자정/보존, 실제 중앙 로그인과 A/B 개인 방문 SQL 결합을 1280/375px에서 검증했다. 기존 43개와 새 통합 2개, 보완 후 최종 45/45 검사 묶음 통과. [검증 기록과 대체 계층의 범위](verification/home-data-step6/README.md). 운영에는 배포하지 않았다.

로컬 A/B 통합 환경 중심. 배포 전에 Step 1~5와 기존 기능의 결합을 검사한다.

- 실제 SQL/API와 브라우저로 글·댓글 생성→홈 갱신→해당 글 이동→삭제 반영을 네 종류에서 검증한다. 공개/비밀 방명록과 그 댓글, 비공개뿐인 사이트, 데이터 없는 사이트를 포함한다.
- 익명/A/B/로컬 관리자 및 계정 전환에서 공개 집계가 같고 비공개 정보가 HTML·응답·건수에 남지 않는지 확인한다.
- A 로그인→A/B 이동, 중앙 왕복, 새 탭·새로고침·직접 글 주소·뒤로/앞으로·미저장 취소와 방문 중복 방지를 함께 검사한다.
- 한국 자정, 동시 탭, 저장소 차단, 서버 장애·늦은 응답·재시도·캐시 갱신, 중복 방지 데이터 정리를 검사한다.
- 데스크톱/모바일/키보드 및 기존 회원 작성·방문자 인식·관리자·설정·콘텐츠 메뉴 회귀 검사를 실행한다. 변경으로 고정 숫자에 의존하던 기존 검사는 새 의미에 맞게 갱신한다.

완료 기준: 재현 가능한 통합 검사와 영향받은 회귀 검사가 통과하고 결함을 보완한다. 기록에 실제 SQL 검사와 mock/UI 검사의 범위를 구분한다. 운영에는 적용하지 않는다.

## Step 7. A/B 운영 업그레이드와 실제 검증

완료: A/B 개인 SQL·방문 Edge·Pages 배포, 서버 재실행과 파일 64개씩의 일치, 실제 홈/글 주소/로그인·이동·작성/방문 중복 검증. 테스트 글 정리와 기존 데이터·회원 연결 보존 확인. 배포 중 추가된 B의 무관한 글은 보존했다. [운영 검증 기록](verification/home-data-step7/README.md) · [복구 절차](home-data-deployment.md). 중앙 배포는 없었다.

앞 단계의 완료를 확인한 뒤 운영에 반영한다.

- A/B 콘텐츠·프로필·설정·회원 연결과 배포 버전을 비공개로 백업한다. 기존 코드/데이터/설정으로 돌아갈 절차와 새 통계의 보존 방안을 기록한다.
- 개인 서버 SQL·필요 함수·Secrets를 먼저 적용하고 이전 개인 화면과의 호환성을 확인한 뒤 A/B Pages를 배포한다. 중앙 변경이 실제 필요해진 경우에만 해당 변경과 호환성을 별도로 검증·배포한다.
- A/B 실제 공개 글·건수·댓글과 최근 글 이동, 로그인/익명/계정 전환, TODAY/TOTAL의 재로드 중복 방지를 검증한다. 운영 자정·장애·비공개 조작을 무리하게 재현하지 않고 로컬 검증 근거를 연결한다.
- 데이터가 없는 검증 항목에 임시 콘텐츠를 만들면 실행 ID를 기록하고 해당 항목만 정리한다. 운영 검증 방문도 정책상 실제 방문 집계에 포함하며 숫자를 임의로 되돌리지 않는다. 활동 날짜/건수의 시간 경과는 보존 비교에서 구분한다.
- 기존 회원 연결·콘텐츠·설정의 보존과 배포 산출물 일치, 마이그레이션 재실행 안전성을 확인한다. 의도한 설정 UI 변경과 신규 통계를 구분하여 기록한다.
- 배포 커밋·함수/SQL 버전·검증/정리 결과와 복구 절차를 남기고 백로그 3번을 실제 완료 범위에 맞게 갱신한다. 백로그 6번에서는 이번 최소 주소 처리만 완료 근거로 연결하며 전체 완료로 표시하지 않는다.

완료 기준: 실제 A/B 데이터 표시·글 이동·방문 집계와 기존 인증/작성/이동이 동작한다. 테스트 콘텐츠 정리·기존 데이터 보존·복구 기록까지 완료한다. 배포나 검증이 실패하면 미완료로 남긴다.

## 순차 실행 규칙

- 요청받은 Step의 선행 단계 완료 기록과 구현·검증 근거를 먼저 확인한다. 이전 Step이 미완료면 즉시 중단하고 부족한 항목을 알린다.
- 각 Step의 코드·문서·검증을 마친 후 상태를 갱신한다. 다음 Step을 자동으로 실행하지 않는다.
- Step 1~6은 로컬 구현·검증이며 운영 배포는 Step 7에서 수행한다.
- 검증 기록은 `docs/verification/home-data-stepN/`에 남긴다. 조건부 정책 변경은 변경 이유·기존 데이터와 권한에 미치는 영향도 기록한다.
- 공개범위 관리 UI, 일촌 공개, 개인 미읽음 알림, 방문자 명단, 전체 분석 서비스, 화면 확대, 전체 임시저장 기능은 이번 범위에 넣지 않는다.
