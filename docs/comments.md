# 공통 댓글

## 적용 화면

게시판 상세, 사진첩의 각 글, 날짜별 다이어리의 각 일기, 방명록의 각 글에 댓글 목록/작성/본인 수정/삭제를 연결했다. 기존 작은 글씨와 댓글 배경, 이름/본문/날짜 배치를 유지한다. 날짜는 한국 시간 `MM.DD HH:mm`으로 고정한다.

- `comments.js`: 네 화면이 공유하는 댓글 UI. 20개씩 시간/ID 오름차순 조회, 이전/다음 페이지, 새로고침.
- `comments-repository.js`: 부모 글 확인, 댓글 읽기/저장/삭제와 revision 충돌 처리.
- `visitor-session.js`: 방명록과 댓글의 관리자/방문자 클라이언트 선택, 신원 확인, 닉네임, 최초 익명 인증을 공유한다.
- `supabase/migrations/202609130008_comments.sql`: 댓글 테이블, 부모 FK, RLS, 작성 제한.

## 작성과 신원

댓글은 일반 텍스트 1~1,000자이며 HTML을 실행하지 않는다. 이름은 방명록과 동일한 1~20자 규칙이다. 닉네임은 표시 이름이지 고유 신원이나 관리자 권한 증명이 아니다.

CAPTCHA나 가입 폼은 없다. 읽기만 할 때는 익명 계정을 만들지 않으며, 처음 저장할 때만 Supabase 익명 인증을 한다. 방명록에서 이미 만든 브라우저 세션과 닉네임을 댓글에서도 그대로 재사용한다. 관리자는 관리자 계정으로 작성한다.

다른 브라우저/기기로 이동하거나 사이트 데이터를 삭제하면 기존 댓글의 작성자 권한은 복구되지 않는다. 익명 인증과 Auth 가입 IP 제한은 유지해야 한다. CAPTCHA가 없으므로 계정을 새로 만드는 봇에 대한 방어는 제한적이다.

## DB 권한

- 댓글마다 네 부모 FK 중 정확히 하나만 지정한다. 부모/작성자/이름/생성 시각/revision은 일반 API로 변경할 수 없다.
- 공개 부모 글의 댓글은 누구나 읽을 수 있다. 비공개 방명록 댓글은 방명록 작성자와 관리자만 읽을 수 있다.
- 조회뿐 아니라 생성·수정·삭제도 부모 조회 권한을 요구한다. 공개 방명록에 댓글을 쓴 사람이 이후 그 방명록이 비공개가 되어 조회 권한을 잃으면 자기 댓글도 조회·수정·삭제할 수 없다.
- 본인 댓글만 수정한다. 관리자도 타인의 본문을 수정할 수 없으며 삭제만 가능하다.
- 부모 글 삭제 시 FK CASCADE로 댓글도 삭제한다. UI에서 부모 삭제 성공 시 해당 댓글 초안도 정리한다.
- 방문자 신규 댓글은 네 메뉴를 합쳐 10초에 1개, 연속 24시간 창당 100개로 제한한다. 별도 private 카운터를 잠가 동시 생성과 삭제 후 재작성을 통한 우회를 막는다. 관리자는 빈도 제한을 받지 않는다.
- `can_read_comment_parent`는 security invoker 함수다. 부모 테이블의 RLS를 그대로 적용하며 비공개 확인을 위해 권한을 우회하지 않는다.

## 초안과 실패

다른 메뉴 이동·문서 이탈 시 댓글 초안을 확인창 없이 폐기하며 history 복귀로 복원하지 않는다. 같은 메뉴의 댓글 페이지 이동 및 같은 화면의 인증 갱신·일시 오류에서는 메모리 초안을 유지한다. 영구 임시 저장은 아니다. 역할 변경/방문자 세션 변경 시 댓글 초안과 표시 중인 댓글을 정리하고 다시 조회한다.

저장 응답이 유실되면 같은 UUID/작성자/본문을 확인해 중복 등록을 피한다. 수정/삭제는 revision을 비교하고 충돌 시 덮어쓰지 않는다. 저장 실패 후 부모와 댓글을 재조회하며, 조회에도 실패하면 이전 댓글과 폼을 숨긴다. 초안은 메모리에 남아 재시도 후 복원된다.

창으로 돌아오거나 댓글 새로고침/메뉴 재진입 시 권한을 다시 확인한다. Realtime 구독은 사용하지 않아 다른 창에서 바뀐 글은 즉시 화면에 반영되지는 않지만, 이후 DB 요청은 항상 현재 RLS의 보호를 받는다. 이미 전달된 공개 내용을 비공개 전환으로 소급 회수할 수는 없다.

## 검증

사용자가 008 SQL 적용 성공을 확인했다.

- `scripts/verify-comments-db.mjs`: 로컬 PGlite에서 실제 부모 마이그레이션과 함께 네 FK/RLS, 부모 비공개 전환, 본인/관리자 권한, 불변 열, 충돌, 삭제 전파, 작성 제한 검증.
- `scripts/verify-comments-writing.mjs`: 실제 SDK + 모의 Auth/API로 네 실제 화면, 닉네임 공유, 최초 익명 인증, 초안, 실패/응답 유실/충돌, 권한 상실, 관리자 삭제, 페이지, 데스크톱/모바일 검증.
- `scripts/verify-comments-live-read.mjs`: 실제 프로젝트 GET 공개 조회만 수행한다. 실제 댓글이나 익명 계정을 생성하지 않는다.
- 기존 게시판/사진첩/다이어리/방명록 작성 검사의 모의 API에도 댓글 읽기를 추가했다.
- 스크린샷: `docs/verification/comments/`.

실제 방문자 계정의 댓글 작성/수정/삭제는 사용자가 홈페이지에서 확인한다.
