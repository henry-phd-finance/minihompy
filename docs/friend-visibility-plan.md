## 범위와 기본 방향

- 게시판·사진첩·다이어리의 **게시물 단위** 공개 / 일촌 공개 / 나만보기를 지원한다. 폴더별 공개범위·특정 일촌 그룹·친구의 친구는 포함하지 않는다. 기존 공개/나만보기 데이터와 폴더 공개 메타데이터 정책을 보존한다.
- 일촌 공개는 해당 홈 주인과 **현재 확정 일촌인 중앙 회원** 및 검증된 로컬 관리자만 읽는다. 신청 대기는 일촌이 아니다. 일촌 관계가 관리·게시물 수정 권한을 주지 않는다.
- 중앙은 회원·사이트·관계·세션을 확인하고, 본문·댓글·사진·검색용 콘텐츠·조회 결과는 개인 서버/DB에 둔다. 일촌평 작성 permit을 읽기에 재사용하지 않는다.
- 공통 회원 세션을 재사용한다. 추가 로그인/회원 확인 버튼은 만들지 않는다. 중앙 회원 토큰을 개인 Supabase 관리자 JWT처럼 취급하거나 브라우저에 service_role 키를 주지 않는다.
- 서버가 확인한 읽기 권한을 목록·상세·댓글·사진 바이트·홈 요약·달력·글 위치에 함께 적용한다. 임의 쿼리를 받는 범용 DB 프록시 대신 종류별 허용된 요청/응답을 정의한다.
- 기본 표시안은 비로그인/비일촌에게 공개, 일촌에게 공개+일촌 공개, 관리자에게 세 범위다. 홈 요약의 관리자 표시도 포함하여 Step 1에서 기존 정책과의 차이를 확정한다. 방명록 비밀글의 주인/작성자 규칙과 공개 일촌평은 유지한다.
- **각 새 보호 조회에서 현재 관계를 확인**한다. 15분 회원 세션이나 브라우저 관계 캐시가 15분 읽기 허가를 뜻하지 않는다. 중앙에서 끊기가 먼저 확정된 뒤 시작한 권한 확인은 거절한다. 이미 허가된 진행 중 요청의 허용 시간·재검사·사진 전송 경계는 Step 1에서 수치와 시나리오로 확정한다. 분리된 DB 사이의 동시성을 무조건적인 즉시 회수로 설명하지 않는다.
- 중앙 장애 시 새 일촌 전용 조회를 차단한다. 공개 조회와 유효한 로컬 관리자 경로는 유지하고, 회원 인증 실패를 조용히 다른 계정/역할로 바꾸지 않는다. 공개 항목만 조회하는 경우에도 일촌 범위 확인 실패를 빈 목록·0건으로 가장하지 않는다.
- 계정 변경/로그아웃/권한 실패/메뉴 이탈과 탭 복귀에서 이전 응답·사진 blob·권한별 캐시를 적절히 무효화한다. 이미 받은 데이터나 다운로드한 파일을 회수하는 기능은 약속하지 않는다. 미저장 입력은 메뉴 이탈 시 폐기한다.
- 새 기능 준비 전에는 서버에서도 `friends` 저장을 막는다. Step 1~12는 로컬 작업이며 중간 산출물을 운영에 배포하지 않는다.

## 현재 구조와 주요 접점

- `content-access.js`는 로컬 관리자와 visitor를 구분하며 현재 게시물 repository는 직접 PostgREST/RLS로 읽는다. 중앙 회원별 읽기 context와 명시적 서버 API를 추가해야 한다.
- `202609240002_content_visibility.sql`은 public/private 두 값을 허용한다. `member_comments`의 부모 검사, 기존 RLS·공개 전용 RPC가 새 값에서 허용으로 떨어지지 않도록 함께 점검해야 한다.
- `photo-media`는 현재 Authorization이 있으면 로컬 관리자 자격으로 해석한다. 회원 읽기는 별도 명시적 mode가 필요하며 업로드/관리 권한은 확대하지 않는다.
- `home_summary`, `post_location`, 다이어리 달력·페이지 수는 별도 조회 경로다. 본문만 숨겨서는 제목·날짜·건수·댓글 정보 누출을 막을 수 없다.
- 중앙의 verified site→owner와 현재 관계 검증, 개인 member session/family·중앙 grant 검증을 재사용한다. 공개 조회 제한의 gateway 공유 제약을 고려해 무제한 polling을 추가하지 않는다.

## Step 1. 권한·동시성 계약과 최소 실증

상태: 완료(2026-09-24). 선행 두 운영 완료 기록·소스 확인 통과.

- `docs/friend-visibility-contract.md`에 역할×공개범위×조회/댓글 작업 권한표, actor/site/owner/session 결합, API·오류·준비 상태를 확정한다.

- 권한 상실 후 댓글 읽기·쓰기·수정·삭제·작업 결과 조회 정책을 정한다. 기본은 부모 접근이 필요한 작업을 차단하고 관리자 정리를 유지하는 것으로 하며, 예외를 둘 경우 권한표에 명시한다.
- 실제 기존 인증 handler/SQL을 이용해 A→B 회원의 읽기 자격 전달을 최소 실증한다. 검증 실패/중앙 장애/자기 홈 관리자/진행 중 철회 사례와 이후 테스트 행렬을 만든다.

완료 기준: 구현 시 추가 정책 추측이 필요 없는 계약과 최소 실증이 있다. 아직 기능 구현 완료나 운영 적용으로 간주하지 않는다.

## 순차 실행과 기록

- Step 실행 전 직전 Step의 완료 기록·소스·검증 근거를 확인한다. 미완료면 즉시 중단한다. Step 1은 지정한 두 운영 완료 단계를 확인한다.
- 한 요청에서 지정된 Step만 실행하며 다음 Step을 자동 시작하지 않는다. 문서 링크 추가와 구현 변경을 구분해 소스 차이를 판단하고, 선행 구현 결함이면 임의로 후속 Step에 합치지 않는다.
- 근거는 `docs/verification/friend-visibility-stepN/`에 명령·결과·소스 해시·남은 제약으로 남긴다. 실제 로그인/외부 서비스와 fixture 결과를 구분한다.
- 비밀번호·토큰·개인 콘텐츠·운영 백업은 공개 저장소/기록에 넣지 않는다. 기존 미커밋 변경을 보존하며 계획 작성만으로 기능 체크박스를 완료하지 않는다.
