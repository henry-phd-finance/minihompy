# 3단계 검수 — 방문 인식·복귀·로그아웃

2026-09-23 로컬 검증 완료. 운영 DB/함수/Pages는 배포하지 않았다.

## 구현

- 개인 탭의 sessionStorage에 무작위 방문 attempt_id와 원래 상대 경로를 저장한다. 중앙 login pending의 visitAttemptId → complete → visit 또는 logout을 거쳐 동일한 ID가 서명된 방문 티켓에 포함된다. 개인은 현재 탭의 시도와 정확히 일치하는 응답만 표시한다.
- 티켓을 네트워크 요청 전에 주소에서 제거한다. 성공하면 중앙이 검증한 경로, 실패하면 개인 탭에 저장했던 경로를 복원한다. fragment의 미검증 path는 사용하지 않는다. 복원 중 앱 라우터가 원래 메뉴를 덮어쓰지 않는다.
- 가드는 로그인 세션이 아니다. 미완료 왕복은 error 상태이며 재시도 버튼을 제공한다. 성공 시 가드를 지워 새로고침·직접 방문에서 중앙 상태를 다시 확인한다. 동일 문서의 중복 확인은 하나의 요청으로 합친다.
- 버튼과 방문자 이름은 visitor-identity.js의 단일 renderer에서 갱신한다. 관리자 판정/RLS는 개인 Supabase에 남는다.
- 방문자 로그아웃은 중앙 저장값을 삭제하고 확인한다. 현재 사이트 관리자라면 개인 SDK의 local signOut 성공 후 중앙 로그아웃을 진행한다. 저장소 삭제 실패는 완료로 표시하지 않는다. 다른 origin의 개인 세션은 유지되지만 명시적 로그인 없이 중앙 활성화에 사용하지 않는다.
- 개인 health 1.5초, 방문 티켓 확인 10초, 중앙 페이지 API 15초 제한. 중앙 페이지는 재시도와 이전 화면 버튼을 제공한다. 최초 방문은 history를 보존해 이전 화면으로 돌아갈 수 있고, 미완료 가드가 반복 리다이렉트를 막는다.
- 중앙 저장소 접근 실패 시 오류를 보여 준다. 개인 저장소 접근/읽기·쓰기 검증 실패 시 자동 왕복을 시작하지 않는다.
- 뒤로 가기로 복원된 문서도 방문 상태를 다시 확인한다. 취소된 로그인은 기존 중앙 세션을 이용한 방문 확인으로 복귀한다.

## 실행 결과

- 개인 `node scripts/verify-visitor-identity-client.mjs`: 기존 익명 작성자 식별, 가드, 정상 경로 복원, 실패/불일치 티켓 제거, query/hash 유지, 저장소 메서드 및 속성 접근 차단, health/resolve 타임아웃, 중복 요청, 관리자/방문자 이벤트 순서 통과.
- 개인 `node scripts/verify-identity.mjs`, `node scripts/verify-owner-login.mjs`: 통과.
- 개인 `scripts/verify-admin.mjs` (Playwright Chromium): 데스크톱/모바일 단독 관리자 로그인·권한 거부·로컬 로그아웃 통과.
- 중앙 `npm test`: 8개 검사 묶음 통과 (등록·인증·일회성 교환·마이그레이션·방문 발급/검증·레거시 페이지).
- 중앙 `scripts/verify-login-browser.mjs` (Playwright Chromium): 1280/375px ID→비밀번호→B 복귀, 취소·만료·저장소 차단·개인 세션 재사용·개인/방문자 권한 분리 통과. 추가로 B 새로고침, C 직접 방문 시 동일 A 표시와 query/hash 복원, C 방문자 로그아웃, A 잔존 개인 세션의 중앙 자동 로그인 방지, A 재로그인 후 개인+중앙 동시 로그아웃, 중앙 삭제 차단 후 재시도, 중앙 장애 후 이전 화면 복귀 및 명시적 재시도 통과.
- 개인 `npm run build`: 통과.

브라우저 검사는 alice.github.io / bob.github.io / carol.github.io / central.github.io를 서로 다른 origin으로 사용하고 요청을 로컬 파일과 실제 중앙 handler/PGlite SQL로 연결한다. 외부 Supabase Auth/Pages 응답은 모의이며 실제 배포 환경 검증을 대체하지 않는다.

## 의도한 경계

- 중앙 로그아웃은 해당 브라우저의 중앙 세션 저장값을 제거한다. 다른 장치의 중앙 세션, 이미 복사된 토큰의 전역 폐기, 다른 origin의 개인 세션 일괄 종료는 이 단계의 범위가 아니다.
- 원래 개인 탭의 방문 시도 정보가 없는 방문 티켓은 거절한다. 저장소가 지워졌다면 개인 페이지의 재시도로 새 왕복을 시작한다.
- 로그인 이전 중앙 페이지에서 취소하거나 복귀 검증에 실패하면 개인 페이지에서 방문자 확인 재시도가 필요할 수 있다.
