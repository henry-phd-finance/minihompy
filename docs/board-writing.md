# 게시판 작성·수정 연결

## 글쓰기 자료 조사

[B04 원본](../references/board/B04-editor-2010.png)은 [사과의 블로그, 2010-04-04](https://yavadavadoo.tistory.com/268)의 실제 FREE BOARD 글쓰기 화면이다. 직접 이미지와 원문을 확인했다. 크기는 932×531이며 정확한 캡처일은 미확인이다.

확인된 것은 좌측 폴더 유지, 본문 상단의 제목 입력과 폴더 선택, 공지 체크, 첨부 관련 버튼, 에디터 전환, 큰 본문 입력란이다. Safari 경고창이 일부를 가리며 화면 아래도 잘려 있다. 2008년 이전 디자인의 SoT가 아니므로 배치의 보조 자료로만 사용했다. 경고창·배경 스킨·첨부/서식 UI는 옮기지 않았다.

검색어: 싸이월드 미니홈피 게시판 글쓰기 에디터 화면, 싸이월드 글쓰기 에디터, xarsrima 게시판 글쓰기. 이미지 검색의 Amina·Rhymix·현대 블로그 편집기는 타 서비스이므로 제외했다. [2009년 미니홈피 동영상 삽입 설명](https://toycamera.tistory.com/1816)은 HTML/에디터 관련 텍스트 보조 자료일 뿐 작성 화면 SoT로 채택하지 않았다.

이번 폼은 제목·폴더·일반 텍스트 본문·확인/취소로 제한한 기능용 구현이다. B04의 가려진 부분이나 원본 서식 툴바를 정확히 복원했다고 주장하지 않는다. 프레임·바인더·탭은 기존 기준을 유지하고 본문 안의 폼만 추가했다. 원본 이미지와 출처·해시는 기존 게시판 갤러리와 manifest에 추가했다.

## 실제 동작

- 게시판은 `board-repository.js`를 통해 Supabase의 폴더/게시글을 읽는다. `board-data.js`는 과거 시각 검증용 자료로 남겨두었지만 앱에서 로드하지 않는다. 조회 실패 시 샘플로 대체하지 않는다.
- 목록은 서버에서 10개씩 읽고 exact count로 페이지 번호를 만든다. 상세 본문은 글을 선택할 때 별도 조회한다. 시각은 Asia/Seoul로 표시한다.
- 관리자만 글쓰기/삭제를 보며, 수정은 관리자 본인이 쓴 글에만 표시한다. 글을 쓴 사람의 UID는 DB에서 정하고 클라이언트가 넣지 않는다.
- 새 글을 저장하면 저장 응답의 실제 글 상세로 이동한다. 수정 시 폴더 이동도 가능하다. 선택 폴더가 바뀌지 않았다면 기존 페이지를 보존한다.
- 취소는 원래 목록/상세로 복귀한다. 수정한 내용이 있으면 버리기 확인을 받는다. 다른 메뉴 이동·문서 이탈 시 미저장 초안은 확인창 없이 폐기한다. 같은 화면의 인증 갱신·일시 오류에서는 유지한다. 브라우저 저장소에 본문 초안을 보관하지 않는다.
- 저장 중 중복 제출과 폴더 변경을 막는다. 동일 관리자 인증 갱신은 초안/포커스를 유지한다. 로그아웃/권한 상실 시 초안을 지우며, 이전 저장 응답이 늦게 도착해도 화면을 복원하지 않는다. 이미 서버에 도착한 저장 요청을 로그아웃으로 취소할 수는 없다. 요청 직전에도 서버 인증/관리자 RPC를 확인한다.
- 수정/삭제는 조회한 `updated_at`과 일치하는 글에만 수행해 다른 창의 변경을 덮어쓰지 않는다. 권한 없음/삭제됨/경합으로 0행이 반환되면 성공으로 표시하지 않는다.
- 삭제는 명시적으로 확인한 뒤 수행한다. 마지막 페이지가 비면 유효한 이전 페이지로 보정한다. 비동기 읽기는 요청 번호로 늦은 응답의 덮어쓰기를 막는다.

## 범위와 제한

일반 텍스트만 저장/출력하고 HTML을 실행하지 않는다. 댓글·이미지 첨부·서식·공지·임시 저장·폴더 관리·방문자 작성은 아직 미구현이다. 조회수는 집계하지 않으므로 0으로 꾸미지 않고 `-`로 표시한다.

현재 작성자 표시 이름과 다른 메뉴의 설정은 아직 `config.js`에서 읽는다. 합의한 전체 config DB 이전은 다음 별도 단계로 남아 있다. 이 문서의 실제 게시판 연결은 이전 시각 구현/DB 문서의 '샘플 표시 중' 상태를 대체한다.

네트워크가 응답 전에 끊기면 입력을 유지한다. 새 글은 초안에 저장한 UUID를 재시도에서도 사용하고 해당 ID의 기존 내용을 확인한다. 동일 내용이면 기존 글을 반환하며, 내용이 다르면 새 글을 중복 등록하지 않고 목록에서 확인하도록 안내한다. 수정 응답 유실도 현재 저장 내용과 비교한다. `202609130010_board_retry.sql`로 ID INSERT 열 권한을 추가해야 하며 기존 관리자 전용 INSERT RLS는 유지된다.

## 검증

- `verify-board-writing.mjs`: 실제 SDK + 가로챈 테스트 API. 작성/수정/폴더 이동/삭제, 권한 오류, 수정 충돌, 초안 유지, 로그아웃 상태 변경, 115개 글 페이지 묶음, 재조회, HTML 비실행, 데스크톱/모바일 검증. 테스트 글은 운영 DB에 전송하지 않는다.
- `verify-board-live-read.mjs`: 실제 Supabase를 새 브라우저에서 GET만 허용해 공개 폴더/목록, 방문자 버튼 숨김, 레이아웃을 확인한다.
- `verify-board-db.mjs`: 이전 SQL의 로컬 PostgreSQL 권한 검증.
- `verify-navigation.mjs`: 게시판 API는 테스트 응답으로 대체하고 기존 메뉴 15개 시나리오를 검증한다. 상단 로그인 문구를 제외한 HOME 기준 픽셀 동일성을 검사한다.

실제 관리자 계정의 운영 DB INSERT/UPDATE/DELETE는 수행하지 않는다. 재시도 보완에는 위 010 SQL 적용이 필요하다. 통합 검수는 [검수 기록](verification/release/README.md)을 참고한다.
