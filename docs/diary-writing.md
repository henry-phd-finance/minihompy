# 다이어리 저장 연결

## 구현 범위

- `diary_folders`, `diary_entries`를 조회한다. 이전 `diary-data.js`는 과거 시각 복원 샘플로만 남고 실행하지 않는다.
- 기존 D10 달력/본문/폴더/스크롤 디자인을 유지한다. 최초 선택 날짜는 한국 시간의 오늘이다.
- 폴더 선택은 현재 날짜를 유지한다. 월 이동은 가능한 한 같은 일을 유지하고, 짧은 달에서는 마지막 날로 맞춘다.
- 월별 `diary_written_dates` RPC로 일기가 있는 날짜를 표시한다. 공개 읽기 권한으로만 실행하며 본문 전체를 가져오지 않는다.
- 선택 날짜의 일기를 시간/ID 오름차순으로 표시한다. 하루 20개를 넘으면 이전/다음 페이지로 조회한다.
- 관리자만 왼쪽 `쓰기`와 본문 수정/삭제 버튼을 볼 수 있다. 수정은 관리자 본인의 일기만 허용한다.
- 날짜, 시간(분 단위), 폴더, 날씨(선택 안 함/맑음/흐림/비/눈), 일반 텍스트 본문을 편집한다. 날짜 범위는 1900-01-01~9999-12-31이다.
- 본문 입력은 최대 50,000자다. HTML은 실행하지 않고 그대로 텍스트로 표시한다.
- 저장 후 선택 날짜와 폴더를 저장된 일기의 위치로 바꾸고 첫 페이지를 조회한다. 날짜/폴더 이동 시 이전 위치의 달력 표시는 다음 조회에서 갱신된다.

이번 단계는 전체공개 일기만 지원한다. [공통 댓글](comments.md)의 작성·본인 수정·삭제를 지원한다. 비공개 설정, 이미지/서식, 폴더 관리 UI, 함께 쓰는 다이어리는 아직 없다. 기존 가상의 일기/댓글은 실제 DB로 옮기지 않는다.

## 저장 안정성과 권한

- 작성 중에는 달력/폴더 이동을 잠근다. 날짜/폴더는 작성 폼에서 바꿀 수 있다.
- 다른 메뉴 이동·문서 이탈 시 초안을 확인창 없이 폐기하고, history 복귀에서도 복원하지 않는다. 같은 화면의 인증 갱신·일시 오류에서는 유지한다. 영구 임시 저장은 하지 않는다. 로그아웃/권한 상실 시 초안은 지운다.
- 저장 실패는 단계와 오류를 표시하며 폼을 유지한다. 성공 응답을 잃고 다시 저장해도 같은 UUID와 내용이면 기존 일기로 복구하여 중복 생성을 막는다.
- 수정/삭제는 revision 조건으로 다른 화면에서 바뀐 내용을 덮어쓰지 않는다. 충돌 시 작성 내용은 남겨 두고 취소/재조회로 해결한다.
- RLS와 열 단위 권한으로 방문자의 쓰기, 작성자/생성 시각/revision 위조를 막는다. 날짜/시간/날씨/본문 제약과 비어 있지 않은 폴더 삭제 방지도 DB에 둔다.

## 적용 및 검증

사용자가 `202609130005_diary.sql` 실행 성공을 확인했다. 실제 Supabase 폴더/달력 조회도 확인했다. 관리자 실제 저장은 계정 소유자가 직접 확인한다.

- `scripts/verify-diary-db.mjs`: 로컬 PGlite에서 마이그레이션, RLS, 소유권, 날짜/시간/날씨/본문 제약, revision 충돌, FK, 1,000개 초과 일기의 달력 표시.
- `scripts/verify-diary-writing.mjs`: 실제 SDK와 모의 API에서 작성/수정/날짜·폴더 이동/삭제, 초안, 저장 거부/응답 유실/재시도, 충돌, 윤년·월·연도 이동, 페이지 이동, 로그아웃, 오류 복구, 고정 레이아웃, 긴 본문, 스크롤, 데스크톱/모바일 검증.
- `scripts/verify-diary.mjs`: 현재 작성 검사로 연결하는 호환 진입점. 이전 정적 검수 결과는 `docs/verification/diary-step2/`에 보존한다.
- `scripts/verify-diary-live-read.mjs`: 실제 브라우저와 SDK의 공개 조회. GET 및 읽기 전용 달력 RPC 외 요청을 차단하며 실제 쓰기는 하지 않는다.
- 현재 스크린샷: `docs/verification/diary-writing/`.
