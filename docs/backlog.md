- [x] 로그인한 중앙 회원을 서버에서 검증하여 방명록·댓글 작성자로 저장한다.
- [x] 작성자 이름과 미니홈피 정보를 연결한다.
- [x] 다른 브라우저/기기에서도 같은 회원으로 로그인하면 자기 글 수정·삭제와 비밀글 조회가 가능하다.
- [x] 계정 전환·로그아웃 후 이전 작성자의 권한이 남지 않는다.
- [x] 홈 주인의 관리 권한과 방문자의 자기 글 권한을 구분한다.
- [x] 기존 익명 글의 소유권을 보존하고 임의로 중앙 회원에게 이전하지 않는다.

Step 1 정책: 비회원 작성과 기존 익명 글 소유권을 유지한다. 이름이 같다는 이유로 중앙 회원에게 귀속하지 않는다. [상세 계약](member-writing-contract.md).

추가 개선: [공통 회원 확인·자동 갱신 7단계 계획](member-session-plan.md). Step 1~7 완료. 중앙/A/B 운영 적용과 실제 자동 인증·15분 만료 경계 갱신, 테스트 정리·데이터 보존을 확인했다. [Step 7 운영 기록](verification/member-session-step7/README.md). 기존 회원 작성 기능의 완료 상태와 별도로 관리한다.

- [x] 첫 방문 시 작성 세션을 자동 준비하고, 중앙 로그인 유지 중에는 별도 버튼 없이 갱신한다.
- [x] 방명록·댓글의 ‘회원 확인’ 버튼을 제거하고 로그인·인증 오류 처리를 홈페이지 공통 UI로 통합한다.

- [x] B에서 ‘내 미니홈피’를 누르면 로그인한 A의 미니홈피로 이동한다.

### 3. 홈의 실제 데이터 표시

실행 계획: [7단계 구현 계획](home-data-plan.md). Step 1~7 및 A/B 운영 배포·검증 완료. [Step 7 검증 기록](verification/home-data-step7/README.md). 공개 요약 조회 → 최소 글 주소 → 홈 활동 표시 → 서버 방문 집계 → TODAY/TOTAL·설치 연결 → 통합 검증 → A/B 운영 배포 순서로 진행한다.

- [x] 최근게시물을 실제 공개 게시물로 조회하고 해당 글로 이동한다.
- [x] 메뉴별 게시물 건수와 새 댓글 등 활동 정보를 실제 데이터에 연결한다.
- [x] 글이 있는 상태에서 ‘등록된 게시물이 없습니다’가 표시되지 않는다.
- [x] TODAY/TOTAL을 실제 방문 집계에 연결한다.
- [x] 비공개 글의 제목·건수 등 제한 정보가 공개 홈에 노출되지 않는다.

계획 기본값: 한국 시간 기준 같은 브라우저·같은 사이트는 하루 1회 방문 집계. TOTAL은 기능 활성화 이후 실측값이며 기존 수동 숫자는 합산하지 않는다. 글 이동에 필요한 최소 주소 처리는 6번 전체 구현을 기다리지 않고 포함한다. 상세 범위·정책은 실행 계획을 따른다.

### 5. 일촌과 관계 기능

실행 계획: [일촌과 관계 기능 10단계 계획](member-relationship-plan.md). Step 1~10 완료. 중앙/A/B 운영 배포·실제 신청/취소/거절/수락/끊기/재신청·상호 방문/일촌평·권한·테스트 정리와 기존 데이터 보존을 확인했다. - [x] 일촌 신청·수락·거절·신청 취소·관계 끊기를 지원한다.
- [x] 양쪽 미니홈피에서 관계 상태가 일관되게 보인다.
- [x] 일촌 목록과 상대 미니홈피 방문을 지원한다.
- [x] 일촌평 작성과 작성자/홈 주인의 삭제 권한을 구현한다.

설계 기본안: 관계는 중앙 DB의 단일 원본으로 관리하고 개인 사이트가 조회한다. 일촌평 본문은 해당 홈의 개인 DB에 저장한다. Step 1에서 인증·관계 변경 경합·권한 계약을 확정했다. 전체 관리·일촌평과 운영 적용을 완료했다. 팬 기능과 일촌 공개범위는 별도 후속이다. 공개 조회 rate bucket은 실제 runtime의 게이트웨이 주소를 공유할 수 있으므로 트래픽 증가 시 제한 설계를 재검토한다.

## 진행 원칙

- 우선 1 → 2 → 3을 통해 작성·상대 방문·최근 활동 확인 흐름을 완성한다.
- 이어 4의 폴더/기본 공개범위 → 5의 일촌 → 4의 일촌 공개 순서로 의존성을 해소한다.
- 개인 콘텐츠는 개인 DB에 보관하고, 중앙에 추가할 데이터는 기능별로 필요한 범위를 설계한다.
- 화면 크기 조정은 사용자가 다시 요청할 때 검토한다.
