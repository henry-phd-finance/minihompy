# 기능 백로그

2026-09-23 사용자 우선순위 확정. 근거: [A 사용자 관점 기능 검토](functional-review-20260923.md).

1번과 2번은 중앙/A/B 운영 배포·실제 계정 검증까지 완료했다. 3번은 공개 홈 요약·최소 글 주소·실제 홈 표시(Step 1~3)를 로컬 완료했고, 4번 이후는 미착수다. 아래 체크박스는 기능 전체의 완료 조건이다. 1~5번을 필수 기능으로 먼저 진행하고 6~8번은 후순위로 둔다. 번호는 검토 문서와 동일하게 유지한다.

## 필수 기능

### 1. 중앙 회원과 방명록·댓글 작성자 연결

실행 계획: [7단계 구현 계획](member-writing-plan.md). Step 1~7 완료. 중앙/A/B 운영 배포·활성화, 실제 계정 검증과 테스트 콘텐츠 정리, 기존 데이터 보존 확인을 마쳤다. [최종 검증 기록](verification/member-writing-step7/README.md).

상단 방문자 인식과 실제 글의 작성자·소유권을 연결한다. 이름 자동 입력뿐 아니라 개인 서버와 DB의 권한 검증이 필요하다.

- [x] 로그인한 중앙 회원을 서버에서 검증하여 방명록·댓글 작성자로 저장한다.
- [x] 작성자 이름과 미니홈피 정보를 연결한다.
- [x] 다른 브라우저/기기에서도 같은 회원으로 로그인하면 자기 글 수정·삭제와 비밀글 조회가 가능하다.
- [x] 계정 전환·로그아웃 후 이전 작성자의 권한이 남지 않는다.
- [x] 홈 주인의 관리 권한과 방문자의 자기 글 권한을 구분한다.
- [x] 기존 익명 글의 소유권을 보존하고 임의로 중앙 회원에게 이전하지 않는다.

Step 1 정책: 비회원 작성과 기존 익명 글 소유권을 유지한다. 이름이 같다는 이유로 중앙 회원에게 귀속하지 않는다. [상세 계약](member-writing-contract.md).

### 2. 미니홈피 사이 이동과 사용자 상태 표시

실행 계획: [6단계 구현 계획](member-navigation-plan.md). Step 1~6 완료. [운영 검증 기록](verification/member-navigation-step6/README.md). 이동·사용자 구분과 잘못된 관계 표시 제거를 배포했다. 실제 일촌 관계는 5번의 미완료 의존성으로 남긴다.

- [x] B에서 ‘내 미니홈피’를 누르면 로그인한 A의 미니홈피로 이동한다.
- [x] 글 작성자 이름/집 아이콘으로 작성자의 미니홈피에 방문한다.
- [x] 파도타기와 랜덤 방문을 실제 이동에 연결한다.
- [x] 본인/타인/비로그인을 구분하고 본인 홈에서는 일촌신청을 표시하지 않는다.
- [x] 고정 ‘사촌’ 문구와 미구현 일촌신청을 제거한다. 관계 기능 완성 전에는 관계가 있는 것처럼 표시하지 않는다.
- [x] 같은 표시 이름을 사용하더라도 방문자 계정과 현재 홈 소유자를 구별할 수 있다.

의존성: 작성자 방문은 1번, 실제 일촌 관계 표시는 5번과 연결한다.

### 3. 홈의 실제 데이터 표시

실행 계획: [7단계 구현 계획](home-data-plan.md). Step 1~7 및 A/B 운영 배포·검증 완료. [Step 7 검증 기록](verification/home-data-step7/README.md). 공개 요약 조회 → 최소 글 주소 → 홈 활동 표시 → 서버 방문 집계 → TODAY/TOTAL·설치 연결 → 통합 검증 → A/B 운영 배포 순서로 진행한다.

- [x] 최근게시물을 실제 공개 게시물로 조회하고 해당 글로 이동한다.
- [x] 메뉴별 게시물 건수와 새 댓글 등 활동 정보를 실제 데이터에 연결한다.
- [x] 글이 있는 상태에서 ‘등록된 게시물이 없습니다’가 표시되지 않는다.
- [x] TODAY/TOTAL을 실제 방문 집계에 연결한다.
- [x] 비공개 글의 제목·건수 등 제한 정보가 공개 홈에 노출되지 않는다.

계획 기본값: 한국 시간 기준 같은 브라우저·같은 사이트는 하루 1회 방문 집계. TOTAL은 기능 활성화 이후 실측값이며 기존 수동 숫자는 합산하지 않는다. 글 이동에 필요한 최소 주소 처리는 6번 전체 구현을 기다리지 않고 포함한다. 상세 범위·정책은 실행 계획을 따른다.

### 4. 폴더와 공개범위 관리

- [ ] 게시판·사진첩·다이어리의 폴더 생성·이름 변경·정렬·삭제를 지원한다.
- [ ] 글의 폴더 이동과 글이 있는 폴더의 삭제 규칙을 제공한다.
- [ ] 일반 게시물의 공개/나만보기 설정과 서버 조회 권한을 연결한다.
- [ ] 일촌 공개를 실제 관계와 서버 권한 검증에 연결한다.
- [ ] 기존 방명록 비밀글 기능과 주인/작성자 권한을 유지한다.

의존성: 일촌 공개는 5번의 관계 기능 이후 완료한다. 공개/나만보기와 폴더 관리는 먼저 진행 가능하다.

### 5. 일촌과 관계 기능

- [ ] 일촌 신청·수락·거절·신청 취소·관계 끊기를 지원한다.
- [ ] 양쪽 미니홈피에서 관계 상태가 일관되게 보인다.
- [ ] 일촌 목록과 상대 미니홈피 방문을 지원한다.
- [ ] 일촌평 작성과 작성자/홈 주인의 삭제 권한을 구현한다.
- [ ] 본인에게 신청하거나 중복 신청할 수 없다.

착수 시 결정: 관계 데이터 보관 위치와 개인 사이트 간 동기화 방식. 팬 기능의 별도 도입 범위는 일촌 기능과 구분해 결정한다.

## 후순위 기능

### 6. 작성 흐름과 글 주소 보완

부분 완료: 홈 데이터 작업에서 네 종류 글 주소·직접 진입·새로고침/history와 기존 초안 이동 확인을 A/B에 배포했다. [근거](verification/home-data-step7/README.md). 전체 작성 흐름 통일·임시저장/복귀 기능은 후속 범위이므로 아래 전체 항목은 미완료로 유지한다.

- [ ] 메뉴 이동 시 저장하지 않은 내용 확인과 초안 유지 방식을 통일한다.
- [ ] 임시저장 및 저장 후 원래 화면 복귀를 지원한다.
- [ ] 글별 고유 주소와 직접 진입·새로고침·뒤로가기를 정리한다.

### 7. 미완성 메뉴 정리 및 완성

- [ ] 프로필의 키워드·히스토리·42문답·기본정보·인맥·즐겨찾기를 정리한다.
- [ ] 사진첩의 작게보기·슬라이드·스크랩을 구현한다.
- [ ] 검색을 구현한다.
- [ ] 쥬크박스·갤러리·동영상의 빈 화면을 실제 기능으로 연결한다.
- [ ] 미구현 항목은 숨기거나 준비 중 상태를 명확히 표시한다.

### 8. 알림·차단·꾸미기

- [ ] 댓글/답글·방명록·일촌신청 알림과 읽음 처리를 구현한다.
- [ ] 사용자 차단과 반복 작성 제한을 지원한다.
- [ ] 미니룸 편집·BGM·선물 기능의 범위를 정하고 순차 구현한다.

## 진행 원칙

- 우선 1 → 2 → 3을 통해 작성·상대 방문·최근 활동 확인 흐름을 완성한다.
- 이어 4의 폴더/기본 공개범위 → 5의 일촌 → 4의 일촌 공개 순서로 의존성을 해소한다.
- 개인 콘텐츠는 개인 DB에 보관하고, 중앙에 추가할 데이터는 기능별로 필요한 범위를 설계한다.
- 화면 크기 조정은 사용자가 다시 요청할 때 검토한다.
