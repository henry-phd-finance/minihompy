# 관리자 설정

설정 값은 이제 Supabase `public.minihompy_settings`의 단일 레코드(id=1)에 저장한다. `config.js`는 이 값을 읽고 저장하는 코드일 뿐 개인 설정 값의 원본이 아니다. 초기 값은 `202609130003_settings.sql`에 이전 시점의 스냅샷으로 보존했다. 사용자가 해당 SQL을 적용했고 실제 공개 조회를 확인했다.

## 편집 위치

관리자 로그인 후 우측 마지막 **설정** 탭에서 변경한다.

| 좌측 분류 | 편집 항목 |
| --- | --- |
| 기본 설정 | 미니홈피 제목, 브라우저 탭 제목 |
| 프로필 | 이름, 자기소개, 이름 옆 보조 문구 |
| 홈 화면 | 최근게시물 문구 3줄(구버전 호환), 미니룸 말풍선, 일촌평 문구. TODAY/TOTAL은 자동 집계이며 편집하지 않음 |
| 메뉴 관리 | 일반 메뉴 표시 여부, 표시 이름, 순서 |

각 분류에서 수정한 값은 저장할 때 하나의 설정 묶음으로 반영한다. 분류·메뉴 간 이동 시 저장 전 편집 내용은 메모리에 남는다. 다시 불러오기는 미저장 변경을 버릴지 확인한다. 페이지 종료/새로고침은 미저장 변경 경고를 표시한다. 로그아웃·관리자 권한 상실 시 설정 폼과 편집 초안은 제거한다.

## 설정 탭 규칙

- 관리자에게만 보이며 항상 맨 마지막에 한 개만 추가한다.
- 일반 메뉴 목록에 포함하지 않으므로 이름/순서/표시 여부를 편집할 수 없다.
- DB에서도 `settings`를 일반 메뉴 ID로 저장할 수 없다.
- 일반 메뉴를 전부 숨기거나 설정 조회가 실패해도 관리자에게 설정 탭은 남는다.
- 방문자는 `#/settings`를 직접 입력해도 진입할 수 없다. 로그인한 관리자 여부는 DB 함수 결과로 판정한다.
- 일반 메뉴를 모두 숨기면 방문자에게는 메뉴 없음 상태를 보여준다. 숨긴 HOME을 임의로 복구하지 않는다.
- 일반 9개 메뉴가 모두 보이면 관리자에게는 설정을 포함한 10개가 표시된다. 기존 탭 크기/간격을 유지하며 바인더 안 높이에 들어가는지 검증했다.

메뉴 숨김은 탐색 설정이다. 공개 게시판의 API 조회 권한 자체를 비공개로 바꾸는 기능은 아니다.

## 저장과 실패 처리

조회는 방문자도 가능하며 수정은 관리자에게만 RLS로 허용한다. 브라우저에는 payload 열 수정 권한만 주며 레코드 추가·삭제와 revision 수정은 허용하지 않는다. DB에서 문자열/숫자/메뉴 형식과 중복을 검증한다. 수정마다 revision을 올리고 클라이언트는 편집을 시작한 revision이 같을 때만 저장한다. 충돌이나 실패 시 입력을 보존하고 성공으로 표시하지 않는다.

저장 완료 시 제목·프로필·카운터와 메뉴가 바로 반영되며 새로고침 후에도 DB에서 읽는다. DB 조회 실패 시 과거 정적 샘플로 대체하지 않는다. 초기 조회 중/실패 시 설정에 묶인 공통 문구를 숨기며, 로그인 버튼과 프레임은 유지한다. 오류 상태에서는 다시 불러오기가 가능하다.

DB 데이터는 공개 설정이다. 비밀번호, 비밀 API 키, 관리자 권한 정보를 payload에 저장하지 않는다. 접속 URL과 publishable key만 `supabase-config.js`에 남긴다. 다른 메뉴의 샘플 글/이미지 데이터는 원래 config의 항목이 아니므로 이번 이전에 포함하지 않았다.

## 길이 제한

- 미니홈피 제목 1~120자, 브라우저 제목 1~80자, 이름 1~20자.
- 자기소개 최대 2,000자, 보조 문구 최대 80자.
- HOME 문구 각각 최대 500자, 최근게시물 문구는 정확히 3줄.
- 카운터는 0~2,147,483,647의 정수. 현재는 편집 가능한 표시 값이며 실제 방문 집계 기능은 아니다.
- 메뉴는 고유한 등록 ID 최대 9개, 표시 이름 1~20자, 표시 여부는 boolean. 빈 배열/모두 숨김 허용.

UI는 기존 작은 글꼴과 고정 크기를 유지한다. 긴 이름·탭은 말줄임과 툴팁으로 처리하고 HTML 문구는 실행하지 않는다.

## 검증

`verify-settings-db.mjs`: 로컬 PostgreSQL(PGlite 0.5.8)에서 마이그레이션/초기값, 방문자 읽기, 관리자 전용 수정, revision 보호/경합, 잘못된 값/메뉴, 설정 ID 금지 검사.

`verify-settings.mjs` (`verify-config.mjs` 진입점도 유지): 실제 SDK+모의 API로 저장·실패·경합, 모든 메뉴 숨김, 관리자 마지막 탭, 직접 주소 접근 차단, 로그아웃, DB 오류 복구, 데스크톱/모바일 검증.

`verify-navigation.mjs`: DB 설정을 쓰는 15개 메뉴 구성/뷰포트 시나리오와 기존 HOME 픽셀 비교. `verify-admin.mjs`, `verify-board-writing.mjs`, `verify-profile.mjs`는 공유 설정 전환의 회귀 검사다.

실제 프로젝트에서는 설정 조회와 초기값을 확인했다. 관리자 자격 증명으로 실제 설정을 바꾸지는 않았으며, 저장은 사용자의 브라우저에서 최종 확인해야 한다. [화면 검증 자료](verification/settings/).

방문 통계의 구버전 JSON 필드 `home.today`/`home.total`은 저장 호환을 위해 유지하지만 화면에는 표시하지 않습니다. 활성화와 초기 설치 절차는 [홈 데이터 설치 안내](../setup/README.md#홈-데이터와-방문-통계-설치업그레이드)를 따릅니다.
