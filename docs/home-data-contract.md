# 공개 홈 요약 계약 v1

2026-09-23. [홈 데이터 계획 Step 1](home-data-plan.md). 로컬 구현이며 운영에는 미적용.

## 호출과 반환

개인 Supabase의 `public.home_summary(p_menus text[])` RPC를 한 번 호출한다. PostgREST 경로는 `/rest/v1/rpc/home_summary`. SQL 기본 인자는 `['board','photos','diary','guestbook']`. 클라이언트는 `MinihompyHomeRepository.summary(menus?, {signal}?)`를 사용한다. 현재 HTML/홈 UI에는 연결하지 않았으며 Step 3에서 연결한다.

입력은 지원 메뉴의 중복 없는 1차원 배열(0~4개)만 허용한다. null·알 수 없는 값·중복·초과 길이는 SQLSTATE `22023`. 빈 배열은 정상 빈 결과다. 클라이언트는 입력을 먼저 검사하고 visitor 클라이언트만 사용한다. 중앙 회원 작성 세션/관리자 클라이언트/추가 인증을 요구하지 않는다.

서버는 요청 메뉴와 `minihompy_settings.payload.menus`의 `visible=true` 메뉴를 교차 적용한다. 호출자가 숨김 메뉴를 요청해도 응답에서 제외한다. 숨김은 사이트 UI 정책이며 원본 테이블의 비공개 권한을 대신하지 않는다. 설정 행이 없거나 menus가 배열이 아니면 SQLSTATE `55000`; 임의로 전체 메뉴나 0건으로 대체하지 않는다.

반환 형태:

```json
{
  "version": 1,
  "as_of": "2026-09-23T15:00:00+00:00",
  "date": "2026-09-24",
  "timezone": "Asia/Seoul",
  "menus": ["board"],
  "recent": [
    {"kind":"board","id":"10000000-0000-4000-8000-000000000001",
     "created_at":"2026-09-23T15:00:00+00:00","label":"글 제목","today_comments":1}
  ],
  "counts": {"board":{"today":1,"total":1}},
  "today_comments": 1
}
```

- `as_of`는 서버의 statement timestamp다. 호출자가 날짜·현재 시각·회원 ID·글 ID·페이지 크기를 지정할 수 없다. 요청 중 날짜가 바뀌어도 같은 기준으로 계산한다.
- `date`는 `as_of`의 한국 날짜. today의 하한은 한국 자정 포함, 상한은 `as_of` 포함이다. 미래 생성 시각은 전체/최근/댓글에서도 제외한다. 다음날 호출 시 경계가 이동한다.
- `menus`는 허용된 메뉴 ID를 C collation 오름차순 정렬한다. `counts`에는 이 메뉴만 존재하며 0건인 허용 메뉴는 today/total 모두 0이다.
- 최근 글은 전체 허용 메뉴를 합쳐 `created_at DESC, kind COLLATE "C" ASC, id DESC`로 최대 5개다. 글 ID가 다른 종류에서 같아도 `(kind,id)`로 구분한다. 수정 시간이나 다이어리의 사용자가 지정한 작성 날짜는 새 글 기준이 아니다.
- `label`은 제목(게시판/사진첩), 본문 요약(다이어리/방명록)에서 HTML 모양의 태그·Markdown 링크 대상/기본 강조 기호를 제거하고 공백을 정리한 최대 120 문자다. 엔티티를 HTML로 디코딩하지 않는다. 남은 기호나 빈 문자열도 허용하므로 화면은 `textContent`로 넣고 빈 label은 ‘제목 없는 글’ 등으로 표시해야 한다. 이 함수는 HTML sanitizer가 아니며 HTML 삽입 용도로 사용하면 안 된다.
- `today_comments`는 선택된 공개 부모 글에 오늘 작성된 댓글 수다. 오래된 글의 오늘 댓글도 포함한다. 최근 항목의 동명 필드는 그 글에 달린 오늘 댓글 수다. 댓글 본문·작성자 ID·인증 정보는 응답에 없다. 읽음/미읽음이 아니다.
- 정상 0건은 `recent:[]`와 실제 0인 count다. 오류/abort는 예외로 전달하며 정상 빈 결과로 바꾸지 않는다. repository는 반환 필드/종류/ID/시각/정수/길이를 검사하고 원시 DB 오류 메시지는 화면에 전달하지 않는다.
- 별도 로컬 캐시를 두지 않는다. 취소 signal은 Supabase query에 전달한다. 실제 화면에서 이전 응답을 무시하고 재조회하는 정책은 Step 3에서 구현한다.

## 공개 조건과 권한

`public.home_summary`는 빈 search_path를 가진 SECURITY DEFINER 함수다. 호출자의 RLS 결과를 집계하면 관리자에게 비밀글 건수가 섞일 수 있으므로, 호출자의 권한과 무관한 명시적 공개 조건을 사용한다. 함수 안의 테이블·헬퍼 참조는 모두 스키마를 지정하며 동적 SQL을 사용하지 않는다.

| 종류 | 현행 공개 조건 |
| --- | --- |
| 게시판·사진첩·다이어리 | 현재 스키마는 공개 글만 저장하며 공개 SELECT 정책을 사용한다. |
| 방명록 | `visibility='public'`인 글만 포함한다. 로컬/중앙 회원 작성자 구분 없이 동일하다. |
| 댓글 | 부모 `(kind,id)`가 위 공개 글 집합에 포함되고 댓글 생성 시각이 오늘인 경우만 포함한다. |

익명 `anon`과 `authenticated`만 공개 함수 실행 권한을 명시적으로 받는다. PUBLIC 기본 실행 권한과 service_role 명시 권한은 제거한다. 테이블의 기존 RLS·쓰기 권한은 변경하지 않는다. RPC가 관리자/글 작성자의 기존 비밀글 조회 권한을 사용하지 않는다. DB 소유자의 관리 권한은 별개다.

`private.home_summary_at`은 테스트의 자정 경계를 재현하기 위한 내부 함수다. 인자로 시각을 받지만 anon/authenticated/service_role에 실행 권한이 없고 노출 RPC로 사용하지 않는다. `private.home_summary_text`도 공개 실행 권한이 없다.

**백로그 4번에서 일반 게시물/폴더의 공개범위를 추가할 때는 이 함수의 공개 조건도 같은 변경에서 확장해야 한다.** SECURITY DEFINER 함수에 원본 테이블 RLS 변경만 적용하면 충분하지 않다. 그때 일반 비공개/일촌 글·댓글의 메타데이터 제외를 실제 SQL 검사에 추가한다. 아직 없는 공개범위 UI나 미래 정책을 이번 Step에서 구현한 것으로 간주하지 않는다.

## 데이터·성능·배포 경계

마이그레이션 `202609230005_home_summary.sql`은 함수와 읽기 인덱스만 추가한다. 기존 콘텐츠·프로필·설정·회원 연결 행을 수정하지 않는다. 동일 파일 재실행이 가능하며 인덱스는 IF NOT EXISTS, 함수는 CREATE OR REPLACE를 사용한다. 실제 운영 적용/배포 이력 관리는 Step 5/7에서 연결한다.

단일 RPC/SQL 스냅샷 안에서 공개 글 메타데이터·오늘 댓글을 집계한다. 전체 본문을 브라우저로 전송하지 않으며, 최근 5개로 제한한 뒤에만 label 원문을 읽는다. 메뉴 수 최대 4, 최근 항목 최대 5, label 최대 120 문자다. 정확한 전체 건수는 공개 행 수에 비례한 집계 비용이 들며 상수 시간 캐시라고 주장하지 않는다. 전역 최근글 인덱스(사진/일기), 공개 방명록 인덱스, 댓글 날짜 인덱스를 추가하고 게시판은 기존 최근글 인덱스를 재사용한다.

중앙 저장소, 방문 집계, TODAY/TOTAL, 실제 글 주소, 홈 화면 변경은 이 Step의 범위가 아니다.

## Step 3 화면 연결과 표시 수명

`home-activity.js`가 홈 생성 시 `home-repository.js`를 호출한다. 기존 240×44 최근게시물 영역과 프로필·미니룸·회원 이동을 유지하며, 공개 최근 글 최대 5개와 메뉴별 `오늘 / 전체`, 오늘 댓글을 표시한다. 각 글의 native anchor는 Step 2 주소 생성기를 사용한다. 제목 없는 글은 ‘제목 없는 글’, 긴 제목은 말줄임과 전체 title/접근성 이름으로 처리한다. 제목은 textContent만 사용한다.

기존 `home.recentEmptyLines` 설정은 실측 빈 상태를 덮어쓰지 않는다. 설정 데이터 자체는 보존하며, TODAY/TOTAL은 아직 이번 변경 대상이 아니다. 실제 방문 수 연결은 Step 4~5이다.

- 로딩 때 이전 목록·숫자를 즉시 제거한다. 정상 0건·숨김 메뉴만 존재·조회 실패를 구분한다. 실패/8초 초과는 재시도 버튼을 제공하며 0건으로 바꾸지 않는다.
- 홈 재진입마다 재조회한다. 글/댓글 저장·삭제 후 홈으로 돌아오면 이전 스냅샷을 재사용하지 않는다. 설정 변경 시 앱이 홈을 다시 생성해 현재 보이는 메뉴만 요청한다.
- 계정 변경/작성 권한 초기화, focus/pageshow, visibility 변경 시 표시를 무효화한다. 숨겨진 탭에서는 목록을 비우고 요청하지 않으며 다시 보일 때 조회한다.
- 서버 push 구독 없이 표시 수명을 최대 60초로 제한한다. 한국 자정이 더 빠르면 그때 갱신한다. 다른 탭/기기에서 삭제·공개범위를 변경한 결과가 즉시 반영된다고 보장하지 않으며, 포커스 복귀/재진입 시 또는 최대 60초 후 다시 확인한다. 링크 목적지에서도 기존 권한을 재검증한다.
- 새 요청은 이전 요청/타이머를 취소한다. 요청 세대와 현재 DOM 연결을 확인해 취소를 무시한 늦은 응답도 배제한다. 홈에서 나가면 observer가 남은 요청과 갱신 타이머를 정리한다.
- 갱신으로 포커스가 있던 링크/재시도 버튼이 사라질 때 영역에 포커스를 유지하고, 성공 후 같은 링크(없으면 첫 링크)로 복원한다. 그 사이 사용자가 다른 곳으로 포커스를 옮겼으면 이동시키지 않는다.

홈에는 공개 집계만 사용한다. 방문자/관리자 UI 상태가 조회 범위를 확대하지 않으며 서버의 Step 1 공개 조건을 그대로 따른다. 운영 배포 전에는 새 홈 요약 SQL이 먼저 필요하다. 이번 단계에서는 로컬 화면/검증만 연결하고 실제 A/B 배포는 Step 7에 남긴다.
