# 공통 회원 확인과 작성 세션 자동 갱신 — 실행 계획

상태: Step 1~7 완료(2026-09-23). 중앙/A/B 운영 적용, 실제 계정 작성·자동 인증 및 실제 15분 만료 경계 갱신, 테스트 콘텐츠 정리·기존 데이터 보존까지 확인했다.
대상: 개인 사이트 `cyworld`, 중앙 서버 `minihompy-central`.
선행 기반: 회원 작성·회원 이동·홈 데이터 작업의 완료 기록 및 구현을 Step 1에서 확인한다.
관련: [백로그 1번](backlog.md), [기존 작성 인증 계약](member-writing-contract.md).

## 확정 요구사항

- 홈페이지 전체에서 회원 확인과 작성 세션을 공통 관리한다. 방명록과 모든 댓글 영역의 ‘회원 확인’ 버튼을 제거한다.
- 처음 방문하거나 로그인해 중앙 방문자를 확인하는 과정에서 해당 사이트의 작성 세션도 준비한다. 메뉴 클릭마다 새 증명을 발급하지 않는다.
- 유효한 작성 세션을 재사용한다. 작성 세션은 최대 15분으로 유지하되 중앙 로그인이 유효하면 사용자 조작 없이 갱신한다. 활동 자체로 만료 시각을 무조건 연장하지 않는다.
- 자동 갱신은 현재 화면을 떠나거나 새 창을 열지 않는다. 같은 화면의 작성 내용·포커스를 유지한다.
- 중앙 로그인 만료와 서버·네트워크 오류를 구분한다. 로그인 및 오류 재시도는 상단 공통 UI에서 제공한다. 개별 작성 영역에는 상태 안내만 표시한다.
- 메뉴를 벗어나면 해당 메뉴의 미저장 글·댓글·수정 입력과 첨부 선택을 버린다. 돌아와도 복원하지 않는다. 메뉴 이동을 초안 보존용 확인창으로 막지 않는다.
- 로그아웃·계정 전환 시 이전 계정의 입력과 비밀글을 정리한다. 서버에 저장된 글과 첨부는 메뉴 이동으로 삭제하지 않는다.
- 방문자 표시만으로 작성 권한을 인정하지 않는다. 사이트·회원·중앙 로그인 세션에 연결된 서버 검증과 소유자 권한 분리는 유지한다. 비회원 작성 정책도 유지한다.

## 현재 구현과 설계상 확인할 점

- `visitor-identity.js`와 중앙 `public/visit-flow.js`는 방문자 확인을 위해 중앙 페이지를 왕복한다.
- `member-writing-runtime.js`의 `authorize()`는 별도로 중앙 `public/writing-flow.js`에 이동하고, 개인 `login/writing.html`에서 일회용 증명을 교환한다. 현재 작성 영역이 이 흐름을 버튼으로 시작한다.
- 중앙 로그인 자격은 중앙 origin의 localStorage에 있다. 개인 페이지에서 직접 읽을 수 없으며, 숨은 iframe에서도 브라우저의 저장소 분리·차단 때문에 같은 로그인 상태를 읽는다고 가정할 수 없다.
- 기존 계약은 갱신마다 새 중앙 증명을 요구한다. 화면 이동 없는 갱신을 위해 서버 간 갱신 위임 등을 도입한다면 기존 계약 변경과 별도의 제한된 자격 설계가 필요하다. 중앙 로그인 토큰을 개인 사이트에 복사하는 방식은 사용하지 않는다.
- 메뉴 이동 시 초안 보호 정책은 기존 이동 계획과 달라진다. 이 문서의 최신 사용자 요구를 우선하며 Step 5에서 관련 코드·문서·검사를 함께 정리한다.

## Step 1. 자동 인증·갱신 방식 확정과 최소 실증

상태: 완료. [계약 v2](member-session-contract.md)와 [최소 실증·선행 검증 기록](verification/member-session-step1/README.md). 사이트 한정 서버 갱신 위임을 채택했다. 중앙/A/B 별도 origin 브라우저 프로토타입 10개 그룹 및 기존 실제 SQL/handler 세션 검사 10개 그룹 통과. 프로토타입은 운영 구현이 아니며 Step 2~3에서 실제 API/SQL로 검증한다.

후속 구현이 의존할 인증 계약을 확정하는 단계다. 운영 코드는 아직 전환하지 않는다.

- 기존 세 작업의 완료 기록과 관련 인증 구현을 확인하고, 초기 방문·로그인 복귀·새 탭·새로고침·만료 흐름을 정리한다.
- 첫 중앙 왕복에 방문자 확인과 작성 증명 발급을 결합하는 요청/응답, PKCE·state·복귀 경로 검증을 설계한다. 비로그인 방문에는 작성 자격을 발급하지 않는다.
- 화면 이동 없는 갱신 방식을 비교하고 최소 실증한다. 우선 개인 서버가 최초 검증 때 받은 사이트 한정 갱신 자격으로 중앙에 재검증을 요청하는 방식을 검토한다. iframe의 중앙 저장소 접근 성공에만 의존하는 설계는 채택하지 않는다.
- 갱신 자격의 저장 위치·절대 수명·교체/재사용 처리·폐기·중앙 로그아웃 연동을 확정한다. 중앙 로그인 만료를 넘겨 갱신하거나 개인 서버가 독자적으로 연장할 수 없게 한다.
- 15분을 넘긴 비활성 탭 복귀도 처리할 수 있도록 만료된 작성 토큰과 갱신 자격을 구분한다. 재인증이 필요한 조건과 일시 오류를 명시한다.
- 메뉴 이탈의 범위를 정의한다. 기본값은 다른 메뉴·다른 사이트로 실제 이동하면 폐기, 같은 메뉴 내 목록/상세/페이지 이동은 기존 동작 유지다. 인증 갱신·일시 숨김·포커스 복귀는 메뉴 이탈이 아니다.

완료 기준: 별도 origin 환경에서 최초 발급과 무화면이동 갱신 가능성을 실증하고, 만료·철회·사이트 불일치가 거절되는 근거 및 `docs/member-session-contract.md`를 남긴다. 브라우저 저장소 제한에서도 요구사항을 충족할 방식을 확정하지 못하면 미완료로 기록하고 다음 Step을 시작하지 않는다.

## Step 2. 중앙 발급·갱신·철회 구현

상태: 완료. 선행 Step 1 계약·근거 확인. 중앙 v2 발급/갱신/철회와 로그인·방문 전달을 구현했다. 중앙 전체 15개 스위트, 독립 PostgreSQL 연결 경합·업그레이드 5개, 기존 개인 세션 10개 그룹 및 Pages 산출물 검사 통과. [검증 기록](verification/member-session-step2/README.md). 운영에는 적용하지 않았다.

- 확정된 계약에 따라 방문자 확인과 작성 증명의 결합 발급 및 갱신 API/DB 처리를 구현한다.
- 매 갱신에 중앙 로그인 세션의 활성·만료·버전과 회원/대상 사이트 상태를 검증한다. 사이트 한정 자격과 동시 갱신·재사용 처리 규칙을 적용한다.
- 로그아웃·철회 후 기존 및 새 작성 권한이 차단되게 한다. 기존 클라이언트의 방문자 확인·명시적 작성 인증 흐름은 단계적 배포를 위해 유지한다.
- 중앙에는 개인 글·댓글·비밀번호를 추가 저장하지 않는다. 반환값과 로그에 중앙 로그인 토큰·비밀 자격을 노출하지 않는다.

완료 기준: 실제 SQL 기반 발급/갱신/철회 검사, 중앙 세션 만료, 다른 사이트 자격, 재사용·동시 요청과 기존 인증 회귀가 통과한다. 운영 배포 없음.

## Step 3. 개인 서버의 작성 세션 갱신 구현

상태: 완료. Step 2 완료 근거·중앙 소스 해시 일치 확인. 개인 family/갱신 핸들, 초기 교환·중앙 재검증·일괄 철회·cleanup 재시도를 구현했다. 실제 중앙/개인 v2 통합 14개, PostgreSQL 경합·업그레이드 5개, 기존 인증·방명록·댓글 28개 그룹 통과. [검증 기록](verification/member-session-step3/README.md). 운영에는 적용하지 않았다.

- 개인 `member-writing` 함수와 세션 저장 구조에 초기 교환·자동 갱신을 연결한다. 자격 보관 위치는 Step 1 계약을 따른다.
- 중앙 재검증 결과에 따라 최대 15분의 작성 세션을 발급한다. 갱신 자격이 콘텐츠 작성 자체를 허용하는 토큰으로 사용되지 않게 한다.
- 만료·철회·갱신 불가와 일시 장애를 구분하는 응답을 제공한다. 오류 시 회원 요청을 익명 요청으로 자동 전환하지 않는다.
- 여러 요청의 동시 갱신, 로그아웃과 갱신의 경합, 토큰 교체 및 기존 버전 호환성을 검증한다.

완료 기준: 중앙과 개인 서버의 실제 연결로 초기 교환→만료→갱신→작성, 중앙 로그아웃 후 거절을 검증한다. 회원 자기 글·비밀글·소유자 권한과 기존 익명 작성 회귀가 통과한다. 운영 배포 없음.

## Step 4. 홈페이지 공통 인증 관리와 UI 연결

상태: 완료. Step 3 근거·소스 해시 확인. 첫 방문 자동 교환, 공통 상태·자동 갱신·상단 재시도, 개별 회원 확인 버튼 제거와 입력 보존을 구현했다. 실제 중앙/개인 API 브라우저 7개 시나리오, SQL 댓글 9개 그룹, runtime/전송·기존 인증·댓글/방명록/이동 UI 및 산출물 검사 통과. [검증 기록](verification/member-session-step4/README.md). 운영에는 적용하지 않았다.

- 방문자 확인 왕복에서 받은 증명을 자동 교환한다. 처음부터 로그인된 방문과 사이트에서 새로 로그인하는 경우 모두 연결한다.
- 공통 상태를 준비 중/작성 가능/갱신 중/로그인 필요/일시 오류로 관리한다. 메뉴별 증명 발급을 없애고 여러 작성 영역의 요청을 하나의 갱신으로 합친다.
- 활성 화면은 필요 시 만료 전에 갱신하고, 비활성 탭은 복귀 또는 작업 시 확인한다. 무한 재시도·중앙 왕복 반복을 제한한다.
- 방명록 및 게시판·사진첩·다이어리·방명록 댓글의 ‘회원 확인’ 버튼을 제거한다. 상단에 공통 로그인/오류 재시도와 상태 안내를 연결한다.
- 인증 준비·갱신 중 입력은 유지하되 보호된 조회/저장은 유효한 권한이 준비될 때까지 대기 또는 비활성화한다. 응답이 불명확한 저장 요청을 자동 재전송해 중복 글을 만들지 않는다.
- 계정 전환·로그아웃·다른 탭 알림과 늦은 응답에 대한 기존 보호를 연결한다. 중앙 회원 로그인과 로컬 관리자 로그인을 혼동하지 않는다.

완료 기준: 로그인한 방문자가 별도 버튼 없이 방명록/댓글을 작성하고, 메뉴 이동으로 새 증명이 발급되지 않는다. 갱신 중 화면·입력·포커스가 유지되며 인증 실패 UI는 공통으로 표시된다. 운영 배포 없음.

## Step 5. 메뉴 이탈 시 입력 폐기 정책 적용

상태: 완료. Step 4 완료 기록·소스 해시 일치 확인. 메뉴/문서 이탈 시 초안·첨부 선택 폐기, history 복귀 방지, 진행 중 응답 무효화와 안전한 미사용 파일 정리를 구현했다. 데스크톱/모바일 작성 화면·라우터, 업로드 경합, 실제 API 자동 갱신 입력 보존 및 Pages 산출물 검사 통과. [검증 기록](verification/member-session-step5/README.md). 운영에는 적용하지 않았다.

- 라우터와 글·댓글·수정 폼의 초안 보관/이동 확인 처리를 조사하고, 메뉴 이탈 시 해당 입력을 즉시 정리하도록 통일한다.
- 뒤로가기·앞으로가기·메뉴 복귀로 폐기한 입력이 다시 나타나지 않게 한다. 미리보기 object URL 등 임시 자원을 해제한다. 업로드 중 이탈은 취소/늦은 응답 무효화와 기존 임시 파일 정리 규칙을 적용한다.
- 같은 화면의 인증 갱신 및 일시적 네트워크 오류에서는 입력을 유지한다. 로그아웃·계정 전환은 입력과 제한 데이터를 지운다.
- 기존 초안 보호 검사와 문서를 새 정책으로 갱신한다. 메뉴와 무관한 같은 메뉴 내부 편집 취소 정책까지 임의로 확대 변경하지 않는다.

완료 기준: 입력→다른 메뉴→복귀 및 브라우저 history에서 입력이 사라지고, 자동 갱신 후에는 같은 입력이 남는다. 저장된 콘텐츠·첨부에 영향이 없고 이전 화면의 늦은 응답이 새 화면을 변경하지 않는다. 운영 배포 없음.

## Step 6. A/B 통합·만료·브라우저 제약 검증

상태: 완료. Step 5 완료 기록·소스 해시 확인. 별도 중앙/A/B origin·DB와 실제 로그인/작성 화면·SQL/handler를 연결해 데스크톱/모바일 각각 9개 통합 그룹을 검증했다. 시간 경계·저장소 제약·오프라인·갱신/로그아웃 경합, 기존 작성 권한·홈/방문 집계 회귀 및 Pages 검사 통과. [검증 기록과 환경 제약](verification/member-session-step6/README.md). 실제 Supabase Auth·실시간 운영 만료 확인은 Step 7이며 운영에는 적용하지 않았다.

- 서로 다른 중앙/A/B origin에서 A 로그인→A 방문→B 방문→방명록/각 종류 댓글 작성 및 메뉴 이동을 검증한다. B 관리 권한은 얻지 않아야 한다.
- 제어된 시간/만료 fixture로 15분 경계, 장시간 비활성 후 복귀, 중앙 로그인 만료, 로그아웃과 동시 갱신, 계정 전환, 새 탭·새로고침을 검증한다. 시간 제어 범위와 실제 시계 검증을 구분해 기록한다.
- 중앙/개인 서버 장애, 오프라인 복구, 저장소 차단·서드파티 저장소 제한에서 루프·자동 팝업·입력 유실·오류의 비로그인 오판이 없는지 확인한다.
- 데스크톱/모바일의 공통 안내·키보드 사용성과 기존 작성 권한·이동·홈 방문 집계 회귀를 검증한다. 갱신을 새 방문으로 집계하지 않는다.

완료 기준: 재현 가능한 통합 검사와 영향받은 회귀 검사가 통과하고 결과를 남긴다. 지원하지 못하는 환경은 실제 제약과 공통 오류 동작을 기록하며 핵심 요구 미충족을 완료로 처리하지 않는다. 운영 배포 없음.

## Step 7. 설치·업그레이드 및 중앙/A/B 운영 적용

상태: 완료. Step 6 기록·소스 해시 확인 및 설치·업그레이드 검사 통과. 중앙 004/개인 009와 함수, 중앙/A/B Pages를 순차 배포했다. 실제 A/B 자동 인증·네 종류 댓글·방명록 작성/수정/삭제·권한·로그아웃/전환, 실제 15분 만료 경계 자동 갱신과 입력/포커스 유지, 테스트 정리·기존 데이터 보존을 확인했다. [운영 검증과 범위](verification/member-session-step7/README.md).

- 새 모듈/설정/마이그레이션을 설치·업그레이드 및 Pages 산출물에 연결한다. 신규 설치와 기존 설정·데이터 보존을 검증한다.
- 중앙→개인 함수/DB→A/B Pages 순서로 호환성을 유지하며 배포한다. 배포 전 버전, 복구 순서와 기능 비활성화 방법을 기록한다.
- 실제 A/B 계정으로 최초 자동 준비, 메뉴 이동, 작성·수정·삭제, 자동 갱신, 로그아웃·계정 전환을 확인한다. 실제 만료 경계의 갱신도 검증하고 비밀값 없는 근거를 남긴다.

- 배포 버전·검증 결과·백로그와 계획 상태를 갱신한다.

완료 기준: 중앙/A/B 운영 버전과 실제 자동 인증·갱신이 확인되고 데이터 보존 및 테스트 정리가 끝난다. 로컬 성공만으로 운영 적용 완료를 기록하지 않는다.

## 순차 실행 규칙

- 요청받은 Step을 시작하기 전에 이전 Step의 완료 기록·구현·검증 근거를 확인한다. 이전 Step이 미완료면 즉시 중단하고 부족한 항목을 알린다.
- 각 Step은 해당 범위의 구현·문서·검증까지 마친 뒤 완료로 기록한다. 다음 Step은 자동 실행하지 않는다.
- Step 1~6은 로컬 구현·검증이고 운영 반영은 Step 7이다. 기존 미커밋 작업과 관계없는 파일은 건드리지 않는다.
- 계약 변경은 변경 이유·보안 제약·하위 호환성을 기록한다. 증거는 `docs/verification/member-session-stepN/`에 남기며 비밀값과 실제 입력 본문은 기록하지 않는다.
