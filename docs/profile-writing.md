# 프로필 편집

확인된 '내 소개 > 소개'만 DB에 연결한다. 키워드, 히스토리, 42문답, 기본정보, 내 인맥, 내 즐겨찾기는 빈 본문을 유지한다.

## 적용

Supabase SQL Editor에서 `supabase/migrations/202609130009_profile.sql`을 한 번 실행한다. 기존 글과 설정은 수정하지 않는다. 소개 전용 singleton 테이블과 공개 사진 bucket을 추가한다. 적용 전 조회 오류는 명시적으로 표시하며 로컬 샘플로 대체하지 않는다.

## 편집

- 관리자에게만 소개 아래 수정 버튼이 보인다. 사진, 사진 설명, 표시 폭(1~300px), 이름, 소개 문단을 수정한다.
- 이름과 소개는 각각 '설정의 이름 사용', '설정의 자기소개 사용'을 선택할 수 있다. DB의 null은 기존 설정을 따라가며, 직접 입력한 소개가 빈 배열이면 본문을 표시하지 않는다. 프로필 전용 이름은 다른 메뉴의 작성자 이름을 바꾸지 않는다.
- 소개는 일반 텍스트로 10,000자, 100문단까지 저장한다. 빈 줄이 문단을 구분한다. HTML은 실행하지 않는다.
- 사진은 JPG/PNG/WEBP/GIF, 6MB 이하 한 장이다. 선택 직후 blob 미리보기, 저장 시 업로드한다. 사진 없애기는 이미지 표시를 제거한다. 최초 호수 이미지는 기존 로컬 자산을 참조한다.
- 다른 메뉴 이동·문서 이탈 시 초안과 첨부 선택을 확인창 없이 폐기한다. 같은 화면의 인증 갱신·일시 오류에서는 유지한다. 같은 메뉴의 취소/다시 불러오기는 수정 중 확인을 요청한다. 로그아웃 시 초안과 blob URL을 제거한다.
- 저장 중 중복 제출을 차단한다. 실패 시 입력과 업로드 경로를 유지한다. 응답을 잃은 뒤 같은 업로드를 재시도할 때 기존 바이트가 같으면 재사용한다. DB revision 충돌은 덮어쓰지 않으며 동일한 내용의 저장 재시도는 성공으로 확인한다.

## 권한과 파일

공개 조회, 관리자만 허용된 본문 열 UPDATE. 브라우저 INSERT/DELETE 및 revision/id/timestamp 수정은 차단한다. 서버 트리거가 내용 검증과 revision 증가를 수행한다. 관리자 여부는 기존 DB RPC로 재확인하며 최종 권한은 RLS가 집행한다.

`minihompy-profile`은 공개 bucket이다. 무작위 불변 파일명을 사용하고 덮어쓰기를 허용하지 않는다. 게시된 사진의 삭제는 RLS가 막는다. 저장 성공 후 교체된 이전 사진은 정리를 시도한다. 정리 실패는 저장 성공과 별도로 표시한다. 업로드 후 DB 실패/취소/창 닫기 등의 경우 미참조 파일이 남을 수 있다. 자동 고아 파일 수집은 구현하지 않았다. 이미 공개된 이미지의 외부 캐시까지 회수하지 않는다.

## 검증

- `scripts/verify-profile-db.mjs`: 실제 001/009 SQL을 PGlite에서 실행. 공개 조회, 관리자 수정, CAS, 잘못된 본문, 불변 메타데이터, 파일 삽입/삭제 RLS와 게시 사진 보호 검사.
- `scripts/verify-profile-writing.mjs`: 실제 SDK와 모의 API. 데스크톱/모바일 편집, blob 미리보기, 업로드 실패/재시도, 저장 응답 유실, 충돌, 초안, 설정 상속, 사진 제거, 권한 상실, 조회 실패/재시도, 빈 메뉴 검사.
- `scripts/verify-profile.mjs`: 소개 배치, 이미지, 긴 글, 키보드, 미확인 본문 공백, 1000/375px DPR 1/2 검사.
- `scripts/verify-navigation.mjs`: 기존 HOME 픽셀과 메뉴 탐색 회귀 검사.

화면 검증은 모의 API를 사용하며 실제 프로젝트에 관리자 글이나 파일을 생성하지 않는다. SQL 적용 후 실제 저장은 홈페이지에서 확인한다.
