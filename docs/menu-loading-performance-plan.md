# 다이어리·사진첩 로딩 개선 계획

작성: 2026-09-26. 단계별 요청에 따라 실행한다. Step 1~8 완료. A/B 운영 배포·검증 완료(2026-09-27).

## 목표와 유지할 동작

- 서버 준비 상태 확인의 중복, 다이어리 순차 조회, 사진첩 전체 다운로드 대기, 주인 인증의 반복 왕복을 줄인다.
- 주인 상태는 로그인/세션 복원 시 확인하고 같은 세션에서 재사용한다. 중앙 회원 작성 세션의 15분을 주인 인증 캐시 만료 시간으로 사용하지 않는다. 주인은 개인 Supabase 세션을 따른다.
- 서버는 실제 데이터 요청마다 토큰과 권한을 검사한다. 브라우저의 주인 표시를 서버 권한의 근거로 사용하지 않는다. RLS, 일촌 확인, 파일 보호 및 서버의 경합 방어는 유지한다.
- 로그아웃·계정 전환·인증 만료·권한 거절 시 이전 결과와 권한 상태를 무효화한다. 다른 탭의 인증 변경도 반영한다.
- 디자인·메뉴 경로·작성 동작은 유지한다. 메뉴를 떠나면 작성 초안은 폐기한다.
- 개인 글/사진/일촌 권한을 장기 캐시하거나 공개 URL로 바꾸지 않는다. 메뉴 이탈 시 보호 사진 요청 취소와 Blob URL 해제를 유지한다.

## 실행 규칙

- 요청한 Step의 이전 단계가 하나라도 미완료면 작업을 시작하지 않고 중단한다.
- 각 단계는 구현과 해당 범위의 검증·기록까지 통과해야 완료다. 다음 단계는 별도 요청으로 실행한다.
- Step 1~7은 로컬 작업, 운영 배포는 Step 8에서 한다. 기존 미커밋 변경을 통째로 배포하지 않는다.
- 결과는 `docs/verification/menu-loading-stepN/`에 남긴다. 자격 증명·토큰·개인 콘텐츠는 기록하지 않는다.

## 현재 관찰

비로그인 Chromium에서 A/B 메뉴를 각 2회 열어 측정했다. 중앙 초기 사용자 확인 완료 후 메뉴 클릭부터 본문 로딩 안내가 사라질 때까지의 시간이며, 댓글 완료/모든 이미지 디코딩까지의 시간은 아니다. 과거 버전 대비 회귀 측정은 아니다.

| 메뉴 | A | B |
| --- | --- | --- |
| 다이어리 | 약 2.2초 | 약 2.0~2.2초 |
| 사진첩 | 약 3.4~4.0초 | 약 2.0~2.1초 |

`content-access.js`는 읽기마다 health를 요청한다. 다이어리는 calendar 후 list를 순차 조회한다. 사진첩은 목록 → 모든 사진 → 동일 목록 재조회 후 표시하며 빈 목록도 재조회한다. 주인은 `content-access.js`, `visitor-session.js` 등에서 `getUser`와 `is_minihompy_admin`을 반복 호출한다. 실제 주인/일촌 회원 지연은 Step 1에서 추가 측정한다.

검증/완료 기준: 동시 요청 중복 제거, 재사용/만료/오류/취소 테스트 통과. 준비되지 않은 서버에서는 콘텐츠가 노출되지 않는다. 준비 상태 재사용 중에는 읽기마다 health가 추가되지 않는다.

## Step 3 — 확인된 주인 세션 재사용

상태: 완료 (2026-09-27). 선행 Step 1·2 완료 확인. 로컬 구현·검증 완료, 운영 배포는 Step 8.

- 결과: [Step 3 검증 기록](verification/menu-loading-step3/README.md). 개인 Supabase 주인 세션의 최초 검증 공유, 같은 세션 토큰 갱신 재사용, 인증 변경/거절 재확인과 늦은 오류 차단 구현. 인증 단위/모듈 통합 14그룹 및 공유 작성·사진·설정 회귀 통과. 고정 지연 비교에서 로그인 후 메뉴별 추가 주인 인증 요청 0회 확인.

- `admin-auth.js`를 중심으로 최초 로그인/세션 복원의 주인 검증과 진행 중 요청을 통합한다.
- `content-access.js`, `visitor-session.js`, 읽기 runtime이 확인된 사용자·세션 상태를 공유한다. 조회 전후 검사는 세션 세대/사용자 일치 검사로 수행하고 매번 네트워크 주인 확인을 하지 않는다.

- 로그아웃·다른 탭 변경·사용자 변경·인증 거절·권한 취소 시 무효화/재확인한다. 콘텐츠 단위 접근 거절과 로그인 자체의 무효화를 구분한다.
- 서버/RLS 검사는 유지한다. 공유 모듈을 사용하는 댓글·방명록·설정·저장의 권한 및 계정 전환도 회귀 검증한다.

검증/완료 기준: 유효한 같은 세션에서 메뉴 재진입 및 복수 읽기로 `getUser`/주인 RPC가 반복 증가하지 않는다. 최초 확인 전에는 주인 권한을 부여하지 않는다. 만료·갱신·로그아웃·권한 취소·계정 전환 중 늦은 응답 테스트 통과.

## Step 4 — 다이어리 최신 글 우선 표시와 달력 대기 분리

상태: 완료 (2026-09-27). 선행 Step 1~3 완료 확인. 로컬 구현·검증 완료, 운영 배포는 Step 8.

- 결과: [Step 4 검증 기록](verification/menu-loading-step4/README.md). 최신 날짜·글·건수·페이지 단일 SQL/API, capability 기반 구버전 호환, 최신 글 초점·오늘 작성 기본값, 달력 독립 조회/오류 재시도 구현. 신규 SQL/API 6그룹, 최신 UI 14그룹 및 기존 권한·작성·경로·설치 검증 통과.

- 기본 진입/폴더 변경은 조회 가능한 최신 일기의 날짜·최신 글이 포함된 페이지를 첫 요청 하나로 받는다. 별도의 최신 날짜 탐색 요청은 추가하지 않는다. SQL/API capability와 구버전 호환을 포함한다.
- 달력을 반환 날짜의 월/일로 맞추고 해당 월의 날짜 표시는 독립적으로 조회한다. 첫 진입은 월을 알기 전 달력을 요청하지 않으며, 본문 표시가 달력을 기다리지 않는다. 날짜를 이미 아는 사용자 선택 경로는 calendar와 list를 동시에 요청한다.
- 같은 날짜의 기존 오름차순 정렬을 유지하고 최초에는 마지막 페이지의 최신 글에 초점을 맞춘다. 빈 폴더는 한국 시간 이번 달, 새 작성 기본 날짜는 오늘이다.
- 본문을 달력 응답 완료까지 기다리게 하지 않는다. 달력 오류는 달력 영역에서 재시도할 수 있게 하되 본문 권한/오류 처리와 구분한다.
- 직접 글 주소 진입은 위치 조회 후 올바른 폴더/날짜로 실행한다. 날짜·월·폴더 이동, 페이지 보정, 연속 클릭에서 이전 결과가 반영되지 않게 한다.

검증/완료 기준: 최신 일기와 달력 선택 날짜가 일치하고 숨겨진 최신 글의 정보가 노출되지 않는다. 최신 글 전용 날짜 탐색 왕복 없이 본문을 표시한다. 날짜 선택 경로는 고정 지연 fixture에서 calendar+list의 합산 대기가 사라진다. 달력 날짜 표시·빈 글·오류·직접 주소·공개범위·주인 편집 회귀 통과.

- 빈 목록/이미지가 없는 글의 불필요한 다운로드 후 전체 목록 재조회를 제거한다.
- 사진 다운로드 뒤 최신 여부를 확인하는 목적을 유지하면서 전체 본문/건수를 반복 전송하는 대신 필요한 글의 버전·이미지 연결·현재 조회 권한만 확인하는 경로를 구현한다. Step 1 계약의 최대 2개 글 revision을 확인하는 `content/photo-check` API를 사용한다. 구버전은 기존 재조회 경로를 유지한다.
- 새 API가 필요하면 서버는 대상별 실제 권한을 검증하고 불허/삭제된 글의 메타데이터를 반환하지 않는다. 개수·크기 제한, 구버전 서버 호환, 신규 설치/배포 연결 및 실패 시 동작을 포함한다.
- 서버의 사진 바이트 검증과 다운로드 전후 권한 확인을 단순 삭제하지 않는다.

검증/완료 기준: 빈 사진첩은 목록 한 번으로 완료된다. 재검증 중 삭제·공개범위 변경·일촌 해제·이미지 교체를 탐지하고 오래된 글/사진을 새로 붙이지 않는다. 구버전 호환 및 새 경로의 권한 테스트 통과.

## Step 6 — 사진첩 점진 표시

상태: 완료 (2026-09-27). 선행 Step 1~5 완료 확인. 로컬 구현·검증 완료, 운영 배포는 Step 8.

- 결과: [Step 6 검증 기록](verification/menu-loading-step6/README.md). 목록/본문 우선 표시, 사진별 디코딩·배치 재검증·점진 표시, 개별 실패 재시도, 가까운 사진 우선·동시 4개 유지 구현. 신규 PC/모바일 16시나리오, 실제 SQL/API 기반 사진첩 12시나리오 및 권한·미디어·업로드 이탈·배포물 검증 통과.

- 전체 사진의 `Promise.all` 완료를 화면 전체 표시 조건으로 사용하지 않는다. 조회 완료한 화면 구조를 먼저 표시하고 사진별 로딩 상태를 둔다.
- 각 글/사진은 Step 5 계약에 따른 최신 여부·권한 확인을 통과한 단위부터 표시한다. 느린 사진 하나가 다른 준비된 글/사진을 막지 않는다.
- 현재 화면 가까운 사진부터 요청하고 기존 동시 다운로드 제한을 유지한다. 원본 크기를 무시한 이미지 최적화나 새 썸네일 시스템 도입은 이번 범위에 포함하지 않는다.
- 파일 오류는 해당 사진에서 처리한다. 인증/관계 무효화처럼 전체 접근에 영향을 주는 오류는 보호 콘텐츠를 함께 정리한다.
- 댓글을 올바른 글에 연결하고 중복 마운트를 방지한다. 메뉴 이탈·계정 변경·재조회 시 요청 취소, 늦은 응답 무시, Blob URL 정리를 유지한다.
